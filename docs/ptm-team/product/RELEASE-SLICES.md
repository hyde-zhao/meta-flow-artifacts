## 切片顺序理由

| Slice ID | 为什么先 / 后做 | 不这样切的代价 |
|---|---|---|
| RS-RA-01 | 先让管理者和架构师能以可追溯真实问题单做可信决策，并让合规负责人看到边界有效 | 未验证摄取、事实和结论模型即分发改进，会放大错误建议和数据风险 |
| RS-RA-02 | 以 RS-RA-01 的人工确认记录为前提，让消费者只接收可信输入 | 直接做跟踪没有可靠来源、用户收益和授权边界 |

## 发布门禁提示

- 首版只允许 fixture、static-only、dry-run 和人工审查验证；不得声称 runtime-ready。
- 禁止能力、人工确认状态和下游契约均是 RS-RA-01 的 release blocker。
- ITR 摄取仅在 CP2 确认固定 GET、保存边界和数据分类后进入实现；任何其他外部来源或写操作均为 release blocker。
