| REQ-RA-020 | 数据 | 让系统按可审计策略合并问题单版本并保留 `first_seen_at`、`last_seen_at`、`source_updated_at`、`previous_status` 和 `change_history`。 | P0 | Given 可合并记录，When upsert，Then 保留历史版本/变更，不覆盖已存原始引用；冲突策略和合并结果可复核。 | UC-RA-08 |
| REQ-RA-021 | 功能 | 让测试架构师输出本期与上期/去年同期的环比、同比和分析差异报告。 | P1 | Given 完整比较窗口，When 刷新分析，Then 报告给出六维指标的窗口定义、基数、变化值/变化率和可信度；窗口不足时标记 N/A。 | UC-RA-08 |

| REQ-RA-023 | 数据治理 | 让测试架构师能对既有安装项目根下的 `data/` 内容进行分类、来源追溯和 Owner 标记，区分运行数据（SQLite、WAL/SHM、原始快照、批次/分析元数据）与可交付 support（DAO、schema）。 | P0 | Given 已安装的 ptm-tse 项目，When 执行治理核验，Then 每个受管路径具备类别、来源、Owner、敏感级别与保留状态；未分类项阻断分析发布和自动清理。 | UC-RA-09 |
| REQ-RA-024 | 数据 / 安全 | 让 SQLite、WAL/SHM、原始快照以及含问题单内容的批次/分析产物在运行根内受到一致的最小权限保护。 | P0 | Given 受管运行数据，When 创建或核验，Then 数据目录及 snapshots 为 `0700`，每个数据文件为 `0600`；任一不合格项生成修复清单并阻断后续分析发布，不自动修改真实文件。 | UC-RA-09、07、08 |
| REQ-RA-025 | 交付 / 可靠性 | 让 `dao.py`、`schema.sql` 等 support 文件具有可验证的安装来源和版本关联，并与敏感运行数据的保留/权限规则分开治理。 | P0 | Given 已安装的 ptm-tse 项目，When 校验 support/data 边界，Then support 文件可回链到安装 manifest 或受控版本引用，且不被误当作问题单数据清理；来源缺失或版本错配时阻断写入并给出修复提示。 | UC-RA-09、07 |
| REQ-RA-026 | 生命周期 / 安全 | 让运行数据的保留、导出、清理和销毁由显式数据 Owner 策略控制，默认不自动删除。 | P1 | Given 数据达到候选清理条件，When 未提供数据 Owner 的保留/删除授权，Then 标记待决并保留数据；Given 获得授权，Then 输出可审计的范围、理由和回滚/不可逆说明，执行动作仍需单独运行授权。 | UC-RA-09 |
