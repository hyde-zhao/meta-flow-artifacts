## 明确排除（Out of Scope）

- 不在本场景中自动修改禅道问题单状态；状态流转是否允许应作为后续独立授权确认。
- 不在未获得人工确认时执行扩展测试。
- 不在缺少 rollback readiness 的情况下强制执行会改变环境状态的 ptm-atomic op。
- 不把问题单模糊描述直接推断为事实；无法确认的组网、步骤或修复建议必须进入人工确认。
- 不在本草案中设计新的独立物理组网 YAML；物理组网绘制遵循 `resource/network-topology` 组网集合格式。
- 不把定位结论直接等同于产品缺陷；ptm-te 输出定位证据和候选原因，最终缺陷归因仍需人工确认。

## 使用场景列表

### UC-TE-EX-01：执行 Markdown 表格物理用例

| 字段 | 内容 |
|---|---|
| **使用角色** | 测试工程师 |
| **触发条件** | 测试工程师提供 Markdown 表格形式的物理用例，要求 ptm-te 执行一个或多个用例 |
| **输入** | 物理用例表；核心字段包括三级目录、四级目录、五级目录、用例名称、用例编号、用例级别、组网描述、组网约束、预置条件、测试步骤、预期结果、版本、关键词、测试类型、是否自动化 |
| **处理逻辑** | Given 已提供物理用例；When ptm-te 解析表格行、识别组网、拆解步骤、匹配特性 Skill、生成 ptm-atomic op path；Then 逐步与测试工程师确认并真实执行 |
| **输出/结果** | 执行计划、ptm-atomic op path、rollback stack、操作日志、详细事件日志、执行结论 |
| **前置条件** | 物理用例格式可解析；物理组网映射或绘图能力可用；ptm-atomic CLI / 能力索引可读 |
| **排除情况** | 不在用例字段严重缺失、组网不清或 rollback-readiness 未通过时直接执行 |

**处理流程（文字描述）：**
1. ptm-te 读取 Markdown 表格并选择目标物理用例行。
2. ptm-te 解析用例元信息、组网描述、预置条件、测试步骤和预期结果。
3. ptm-te 根据目录、关键词和 op 引用选择特性 Skill。
4. 特性 Skill 输出步骤语义、参数提取、预期观测和 ptm-atomic gap。
5. ptm-te 绘制 / 绑定物理组网，生成统一执行计划和回滚栈预案。
6. 测试工程师确认执行计划后，ptm-te 逐步执行并记录证据。
7. ptm-te 输出执行结论和双层日志。

### UC-TE-EX-02：执行失败后的定位与调试

| 字段 | 内容 |
|---|---|
| **使用角色** | 测试工程师 |
| **触发条件** | 物理用例执行或问题单回归中出现失败、阻断、预期不匹配或 ptm-atomic 调用异常 |
| **输入** | 失败步骤、ptm-atomic 调用结果、配置回显、流量结果、日志、物理组网绑定、预期结果、rollback stack |
| **处理逻辑** | Given 某步骤失败；When ptm-te 汇聚配置、流量、日志、环境和工具调用证据；Then 输出候选原因、证据链、建议复查动作和后续处理选项，并与测试工程师确认 |
| **输出/结果** | 定位报告、候选原因、补充观测 op path、ptm-atomic gap、是否回滚 / 重试 / 转问题单的建议 |
| **前置条件** | 执行过程已有详细事件日志；可调用必要的 observe / verify / diagnostic ptm-atomic op |
| **排除情况** | 不把候选原因直接写成最终缺陷归因；不在缺少证据时擅自扩大执行范围 |

**处理流程（文字描述）：**
1. ptm-te 识别失败类型：配置失败、流量不符、日志异常、环境不可达、ptm-atomic 缺口、回滚失败。
2. ptm-te 汇聚已采集证据，并判断是否需要补充观测。
3. ptm-te 生成补充定位 op path，例如查询配置、查询命中计数、抓取日志、验证接口状态、检查路由表。
4. 测试工程师确认补充定位动作后，ptm-te 执行只读或低风险诊断动作。
5. ptm-te 输出候选原因和证据链，区分产品缺陷、环境问题、用例问题、ptm-atomic 工具问题和不确定项。
6. 测试工程师确认后，ptm-te 执行回滚、重试、记录 gap 或生成问题单回归输入。

### UC-TE-IR-01：从禅道读取问题单并形成结构化理解

| 字段 | 内容 |
|---|---|
| **使用角色** | 测试工程师 |
| **触发条件** | 测试工程师提供 bug id，要求 ptm-te 执行问题单回归 |
| **输入** | bug id；禅道读取工具 CLI 配置；禅道问题单字段：id、bug 标题、重现步骤、开发定位分析、开发修改自测、测试回归 |
| **处理逻辑** | Given 已提供 bug id；When ptm-te 调用禅道读取 CLI 获取问题单；Then 提取核心字段，向测试工程师复述问题理解并等待确认 |
| **输出/结果** | 结构化问题单摘要、字段缺失列表、问题理解确认记录 |
| **前置条件** | 禅道读取 CLI 可用；凭据由环境或工具配置提供；bug id 有读取权限 |
| **排除情况** | 不自动修改禅道状态；字段缺失时不脑补 |

1. 测试工程师提供 bug id。
2. ptm-te 调用禅道读取 CLI，读取问题单。
3. ptm-te 提取标题、重现步骤、开发定位分析、开发修改自测、测试回归字段。
4. ptm-te 输出“问题理解草案”，包含问题现象、涉及组网、复现条件、开发自测建议。
5. 测试工程师确认或修正理解后，才能进入回归规划。

### UC-TE-IR-02：分析问题单并识别回归组网与重现路径

| 字段 | 内容 |
|---|---|
| **使用角色** | 测试工程师 |
| **触发条件** | 问题单摘要已确认 |
| **输入** | bug 标题、重现步骤、开发定位分析、开发修改自测；组网集合规范；物理组网绘制工具能力 |
| **处理逻辑** | Given 已确认问题理解；When ptm-te 分析重现步骤与开发定位信息；Then 识别问题涉及的逻辑组网、物理组网映射需求、复现前置条件和观测点 |
| **输出/结果** | 回归组网草案、重现路径草案、需要人工确认的组网 / 数据 / ptm-atomic gap |
| **前置条件** | 问题单有可解析的重现步骤或开发定位分析；组网图规范可用 |
| **排除情况** | 不在组网事实不清时直接执行真实回归 |

**处理流程（文字描述）：**
1. ptm-te 从标题和重现步骤识别特性、路径、协议、对象和触发条件。
2. ptm-te 从开发定位分析中识别可能的根因、受影响模块和风险邻域。
3. ptm-te 从开发修改自测中提取开发已验证路径和建议扩展测试点。
4. ptm-te 绘制或选择物理组网，输出与组网集合格式一致的更大物理组网视图。
5. 测试工程师逐项确认组网、复现路径、观测点和不确定项。

### UC-TE-IR-03：规划默认问题单回归步骤

| 字段 | 内容 |
|---|---|
| **使用角色** | 测试工程师 |
| **触发条件** | 问题理解、组网和重现路径已确认 |
| **输入** | 已确认的重现步骤；物理组网映射；ptm-atomic op 列表；rollback contract |
| **处理逻辑** | Given 默认回归按问题单重现步骤；When ptm-te 将重现步骤转换为 ptm-atomic op path；Then 执行 rollback-readiness、ptm-atomic gap 和人工确认检查 |
| **输出/结果** | 默认回归计划、ptm-atomic 原子操作路径、回滚栈预案、执行前确认清单 |
| **前置条件** | ptm-atomic CLI / 能力索引可读；相关 op 具备 rollback_strategy 或已进入补齐计划 |
| **排除情况** | 不默认执行扩展测试点；不执行无回滚保障的状态变更 op |

**处理流程（文字描述）：**
1. ptm-te 按问题单重现步骤生成基础回归路径。
2. 每个步骤映射为一个或多个 ptm-atomic op。
3. 对状态变更 op 执行 rollback-readiness 检查。
4. 缺失 op、缺失反操作或参数不明时，生成 gap 并请求人工确认。
5. 测试工程师确认默认回归计划后，才能进入执行。

### UC-TE-IR-04：确认并执行扩展测试点

| 字段 | 内容 |
|---|---|
| **使用角色** | 测试工程师 |
| **触发条件** | 开发定位分析或开发修改自测中存在额外测试建议，或 ptm-te 识别出风险邻域 |
| **输入** | 开发定位分析、开发修改自测、默认回归计划、已有物理用例、ptm-atomic op path |
| **处理逻辑** | Given 默认回归计划已形成；When ptm-te 从开发信息中提取扩展测试点；Then 逐项说明扩展理由、风险、执行成本和预期证据，并等待测试工程师确认 |
| **输出/结果** | 扩展测试点清单、确认记录、扩展 ptm-atomic op path |
| **前置条件** | 默认回归路径已确认；扩展点具备清晰来源和可验证预期 |
| **排除情况** | 未经人工确认不执行扩展测试 |

**处理流程（文字描述）：**
1. ptm-te 从开发定位分析中提取受影响逻辑、边界条件和潜在回归风险。
2. ptm-te 从开发修改自测中提取开发已覆盖路径和未覆盖邻域。
3. ptm-te 输出扩展测试点候选，并标注来源字段、建议理由和执行风险。
4. 测试工程师逐项批准、修改或拒绝扩展测试点。
5. 仅对批准项生成可执行 ptm-atomic op path。

### UC-TE-IR-05：执行回归并回写禅道回归记录

| 字段 | 内容 |
|---|---|
| **使用角色** | 测试工程师 |
| **触发条件** | 默认回归计划和必要扩展测试点已逐步确认 |
| **输入** | 回归 op path、物理组网、ptm-atomic 能力、回滚栈、禅道 bug id |
| **处理逻辑** | Given 执行计划已确认；When ptm-te 真实执行回归；Then 记录操作日志和详细事件日志，失败时按逆序反操作回滚，完成后生成并回写测试回归记录 |
| **输出/结果** | 回归执行报告、详细事件日志、回滚报告、ptm-atomic gap / PR 信息、禅道测试回归记录 |
| **前置条件** | 真实执行授权已确认；rollback-readiness 通过；禅道回写 CLI / 工具可用 |
| **排除情况** | 不自动修改 bug 状态；回写前需人工确认回归记录内容 |

**处理流程（文字描述）：**
1. ptm-te 按确认的 op path 执行回归。
2. 每一步执行前展示动作、参数、预期结果和回滚策略，等待确认。
3. 执行成功后记录证据并压入 rollback stack。
4. 失败时执行逆序回滚，并记录 primary_failure 与 rollback_failure。
5. ptm-te 生成回归记录草案。
6. 测试工程师确认后，ptm-te 将测试回归记录回写到禅道。
