# CR-170：Canonical Cross-Strategy Reliability N/A Semantics and Admission Worst-State Hardening

## 状态摘要

- **状态**：`closed / cp8_closed / READY_WITH_RISK`；CP2、CP3、CP5、CP8 已批准，S01→S04 已全部完成 CP6/CP7，关闭态全仓测试为 `2195 passed / 0 failed`（99.96s）。
- **来源**：`FU-CR161-007` 的 canonical-hardening 子切片；原 aggregate + CR155 regression 剩余切片不进入本 CR。
- **工作流**：`standard / architecture-major`。
- **当前终点**：CP8 人工终验已通过；本 CR 仅关闭 canonical hardening，后续 Stage3 Launch、FU-006、FU-008、FU-009 均须独立 CR 与明确授权。
- **实现门禁**：四个 Story 已完成限定的 repository-local 实现与本地 `uv run` 验证；全仓 `2195 passed / 0 failed`。真实数据、Stage3、aggregate、CR155 promotion、adapter 生产修改和两条已授权 ref 以外的远端权限仍未开放。

## 变更说明

现有 Gate 1-5 对 `n_a_reason` / `na_reason` 的处理并不一致，且部分路径允许通用 reason 替代字段级 mandatory evidence；代码 probe 已复现 Gate 2、Gate 3、Gate 4 和 Gate 5 的无条件 PASS 逃逸。Gate 1 的对应缺失 claim 会被 `effective_trial_count_unavailable` 最终 BLOCKED 掩盖，因此测试必须同时断言字段判定、blocked claim 和最终 worst-state，而不能只看最终 status。

Gate 6 需要分层处理：`build_shared_gate_summary` 已经能把 artifact `NEEDS_REVIEW` 合并为 summary `NEEDS_REVIEW`，该逻辑应先验证并保留；但 `resolve_admission_policy` 当前只对 T1/T2 的 `BLOCKED/FAIL` 做阻断，T0/T1/T2 的 mandatory Gate `NEEDS_REVIEW` 都会落到 PASS。CR-170 不预设重写正确的底层合并，而是在 CP3 明确两层契约后，对 admission 边界做最小必要硬化。

## 已吸收的评审关注点

| ID | 结论 | 对范围 / 实施方案的修改 |
|---|---|---|
| RV-CR170-01 | “Gate 6 已有 worst-state 传播”只适用于 `build_shared_gate_summary` 层。 | 保留并回归验证现有 `NEEDS_REVIEW` 合并；没有失败证据时修改数为 `0`，禁止无理由重写。 |
| RV-CR170-02 | `resolve_admission_policy` 是独立 admission 集成点。 | CP3 必须冻结 lower-level merge 与 tier/admission decision 的职责边界；T0/T1/T2/T3 的输出契约分别验证。 |

## In Scope

1. 形成 Gate 1-5 mandatory evidence inventory，并为每个适用字段冻结五种业务语义：`PRESENT`、`MISSING`、`NA_WITH_COMPLETE_BOUNDARY`、`NA_WITH_INCOMPLETE_BOUNDARY`、`GENERIC_REASON_ESCAPE`。
2. Gate 1：对 multiple-testing / FDR 等 masked escape 建立字段判定、blocked claim、最终 worst-state 三层断言。
3. Gate 2：修复 split / walk-forward / OOS / purge-embargo 相关 generic-reason 或不完整边界逃逸，保留合法 non-overlap N/A 的显式边界。
4. Gate 3：PIT / survivorship-free universe 缺失时，通用 reason 不得替代 owner 明确、边界完整的字段级 N/A。
5. Gate 4：C3+C4 mandatory 字段缺失、字段级/通用 reason escape 不得产生 canonical PASS；CR-168/169 adapter 继续作为 defense-in-depth 回归对象。
6. Gate 5：三类 slot 的 N/A reason、owner、claim limit、review/trigger 边界与 artifact status 必须进入 Gate status，不能出现 artifact refs 为 `NEEDS_REVIEW` 而 Gate PASS。
7. Gate 6：先验证 `build_shared_gate_summary` 现有 worst-state 合并；仅在证据失败时修改该层。对 `resolve_admission_policy` 冻结并实现 tier policy，使 mandatory `NEEDS_REVIEW` 不得升级为无条件 PASS。
8. 保留现有 public callable、Gate ID、summary/claim 追溯和 CR-168/169 adapter 合同；如确需 schema 变更，必须由 CP3 ADR 明确兼容策略。
9. 修复与 CR-169 已关闭事实、Stage 2 `7/7` 和 `stage3_entry_ready=false` 相关的当前产品基线陈旧指针；历史 Stage 3 记录只标记 `legacy / require-revalidation`，深度 revalidation 留给独立 Stage 3 Launch CR。
