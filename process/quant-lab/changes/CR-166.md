# CR-166 Walk-forward / OOS Evidence Producer Foundation

## 变更描述与目标

在 Stage 2 已完成的合同基础上，为 Stage 3 策略生产建立 Walk-forward/OOS evidence producer foundation。该能力在不连接真实数据湖、不执行真实研究运行的前提下，接收显式提供的 fold manifest、split policy、purge/embargo、fold metrics 和 lineage refs，执行输入充分性、时间顺序、泄漏边界、数值与引用完整性校验，生成确定性 typed C2 evidence，并保守投影到现有 statistical gate、cross-strategy reliability gate 与 StrategyAdmissionPackage。

CR-166 不是 Stage 3 本身，也不声称真实 fold/OOS 证据已可用。真实数据灌入、真实研究运行和真实准入结论必须由后续独立 CR 与数据/运行时授权承接。

## 范围

### In Scope

1. 通用 fold manifest、split policy、purge/embargo、fold metrics 与 lineage refs 的 typed 输入合同。
2. daily multifactor P0 fixture 与 `MLPurgedEmbargoCVPolicy` compatibility P0 fixture。
3. 八类 P0 fail-closed：缺 fold、时间逆序、purge 缺失、embargo 不足、metric 缺失/非有限值、lineage 缺失/不一致、未授权 external/real-data ref 不得解引用、canonical hash 不一致。
4. 稳定 header + versioned typed evidence components 的 C2 envelope；C3/C4 仅预留注册式扩展点，未知组件不能满足 mandatory evidence 或产生 PASS。
5. 向既有 statistical gate、cross-strategy reliability gate 与 StrategyAdmissionPackage 的 3/3 保守投影；不新建平行 gate。
6. deterministic canonical serialization、reason code、input/provenance refs 与可审计 recovery/versioning 合同。

### P1 / CP3 适用性审查

- Event strategy 只评估 envelope compatibility 与适用性；除非 CP3 冻结 event-time vs calendar-time、event window vs fixed window 语义，否则明确 N/A，不交付空壳 producer。
- Runtime authorization resolver 的深度集成不是 P0；P0 只要求对未授权 external/real-data ref 零解引用、零外部操作并 fail-closed。

### Out of Scope

- 真实数据湖/NAS/provider/credential、真实 fold/OOS 数据灌入、真实研究或历史重算。
- C3 economic cost/slippage/impact 与 C4 capacity/liquidity/ADV/alpha-decay 的计算或验证。
- event-specific fold producer、真实 ML training/event feed、外部框架、runtime authorization 服务改造。
- broker、simulation、paper/live、交易、订单、publish、deploy、catalog/store/registry write、Git remote write。
- CR155 晋级；缺失或不可信 evidence 必须保持 blocked/typed_unavailable。

## 不授权范围

- credentials / secret / account read
- production dataset/storage、NAS、provider 或 external framework access
- runtime / broker / simulation / paper / live / trading / order
- catalog/store/registry write、publish、deploy 或 Git remote write
- 真实 fold/OOS 灌入、历史重算或 Stage 3 启动
