# CR-171 Stage 3 Launch / Real-Lake Entry Decision Gate

## 变更描述

将 CR-161 的 `FU-CR161-010` 候选项正式化为 Stage 3 的决策、授权边界与历史事实收敛门。CR-171 决定：采用 current runner 还是 C1-C4 real-producer 路线、是否采用事件锚定的 FU-006 verifier waiver、以及可在后续受控读取中使用的冻结 release 候选范围。它不实施 producer、aggregate、修复、真实计算或运行时行为。

## 目标影响摘要

| 字段 | 内容 |
|---|---|
| 目标引用 | `FU-CR161-010` |
| 整体目标 | 在不启动 Stage 3 的前提下，把入口决策和真实数据只读研究的最小边界变为可审计对象。 |
| 用户目标影响 | 解决“下一步如何安全进入真实数据湖”的决策缺口，不把历史证据误作当前准入。 |
| 独立推进理由 | 该事项同时触及 runtime authorization、架构路线、历史 claim 和 maturity verifier，不能混入 aggregate 或 CR155 promotion。 |
| approve 后会发生什么 | 自动完成 CP0/CP1；CP2 由用户决定路线、verifier 及具体只读范围。 |
| reject / 不确认会阻塞什么 | Stage 3 继续保持未启动；任何 real-lake read 或 activation 仍无授权来源。 |
| 决策负担 | 高。 |

## In Scope

- scoped research-data/lake-read 的授权决策与 deny-default 边界；具体 read identity/release/dataset/date/output scope 由 CP2 冻结。
- current runner 与 C1-C4 real-producer 的路线决策；逐 producer 对冻结 release schema/PIT/lineage 的只读可行性判定。
- 历史 Stage 3 evidence 的判定、legacy/require-revalidation 标注和 report；包括 `docs/components/MULTIFACTOR-RESEARCH.md` 的叙事校正。
- FU-006-first 或事件锚定 waiver 的 verifier 路径决策。
- data release/PIT/lineage/readiness 候选清单及其 gap record。
- `R-CR170-STAGE3-OVERCLAIM` 到 `R-CR170-RUNNER-GAP` 的 machine-readable alias 消费举证。
- CR-032、CR-010、CR-018、CR-031、CR-033、CR-168 tracking debt 的逐项披露与无重叠说明。

## Out of Scope / 未授权事项

- C1-C4 real-data-to-producer mapping、producer binding、real computation authorization，及任何 aggregate orchestration、final SAP、CR155 regression/promotion。
- 历史运行修复、代码修复、backfill、provider fetch、lake/NAS write、catalog/current-pointer mutation 或 manifest rewrite。
- credentials / env / secret / account read，QMT、broker、simulation、paper、live、trading、publish 和 deployment。
- FU-006 / FU-008 的实现，或 CR-032/010/018/031/033/168 历史索引与台账修复。

## Hard Fences

1. **revalidation only judges:** 只允许判定、标注、报告；发现 data/schema/PIT/lineage/code/manifest/evidence 缺陷必须路由为 follow-up，不得在 CR-171 修复或重跑。
2. **read is not computation:** CP2 的 scoped lake-read 决策不授予 real computation 或 producer binding；若选 C1-C4，该授权只属于后续 Real-Evidence Activation CR。
3. **claim ceiling:** 在独立证据与授权出现前，`stage3_started`、`stage3_entry_ready`、`real_evidence_available`、mature admission PASS 均必须为 false。
4. **subject adjacency is not overlap:** CR-010/018 与 data lake 主题强邻接，但本 CR 只能定义新冻结 release 的只读研究边界；不得重开其 provider/lake-write/publish/current-pointer/production close actions。
