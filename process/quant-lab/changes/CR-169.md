# CR-169：C4 Capacity / Liquidity / ADV Evidence Producer Foundation

## 状态摘要

- **状态**：`closed / cp8_closed / ready_with_risk`；5/5 Story 的 CP6/CP7、Stage 2 合同 `7/7` 核验、CP8 人工批准及提交后 repository suite `2159 passed / 0 failed` 均已完成。Stage 3 仍未启动。
- **来源**：`FU-CR161-005`（CR-161 follow-up）。
- **工作流**：`standard` / `architecture-major`。
- **阶段定位**：在已记录为完成的 Stage 2 合同边界内增强 fixture/static C4 evidence chain；不重开 Stage 2，不启动 Stage 3，且 `stage3_entry_ready=false`。
- **主分支基线**：从包含已关闭 CR-168 的 `work/cr168-economic-cost-impact-evidence` 派生；不得回退到未包含 CR-168 的旧 `master`。

## 变更说明

本 CR 为 C4 Capacity / Liquidity / ADV 建立一个 fixture/static-only、可复算、确定性且 fail-closed 的 typed evidence producer foundation。它复用 CR-166/CR-168 的 neutral strategy evidence envelope 与 typed component catalog，但拥有独立的 C4 计算输入合同；C3 和 C4 只在经 CP3 冻结的最小关联头及严格 Gate 4 联合适配器处关联。

本 CR 的目标不是证明真实容量、真实流动性或真实 ADV，而是明确这些真实能力尚不可用时的 typed/static 合同与安全失败路径。完成后允许声明的是“fixture Gate 4 合同兼容”；不允许声明真实 capacity readiness、aggregate admission PASS、Stage 3 就绪或 CR-155 promotion。`stage2_complete=true` 只是既有合同状态，不蕴含 Stage 3 可进入；在任何 Stage 3 entry claim 之前，必须完成本 CR 的 7/7 Stage 2 合同核验、按独立 CR/CP0 与用户授权决定的 canonical Gate 4 全局 N/A 语义硬化、独立 verifier lane 与 Stage 3 data/runtime authorization。

## In Scope

1. 激活一个正式、版本化的 `capacity_liquidity@v1` C4 typed component；不创建平行 envelope、registry 或 admission gate。
2. 定义只接收显式合成或静态输入的 C4 输入合同，包括 synthetic ADV / participation、capacity curve、liquidity sizing、单位/货币/日历/时点/期限、lineage/provenance/authorization 与 no-real-data 限制。
3. 提供透明、可审计、确定性的 fixture/static 容量、流动性、ADV proxy 计算与 availability/outcome/reason code/lineage/canonical identity。
4. 冻结 C3/C4 最小关联头及其关联校验规则；C3/C4 各自的计算字段和 component semantic hash 域保持独立。
5. 新增严格的 C3+C4 Gate 4 fixture compatibility adapter：仅将经过类型/版本/identity/limitation 验证的两个 component 组合为精确七字段 flat payload，并对 canonical Gate 4 的联合消费结果施加 postcondition。
6. 保留 CR-168 C3-only adapter 的 absent-C4 fail-closed 回归；不得改变其 denylist 或把 C4 present 路径塞入其中。
7. 提供两个 fixture 族：daily multifactor synthetic fixture 与 daily/ML multi-strategy-type compatibility fixture；二者验证相同 C4 算术合同，而非真实市场差异。
8. 维持 `CR-155` admission package 为 `BLOCKED`、`paper_candidate=false`，并在 C4 fixture 测试中证明其未被提升。
9. 保持 alpha-decay calculator=`0`；其归属与方法评估由 `FU-CR161-008` 独立 follow-up 承担，本 CR 不实现。

## Out of Scope / 未授权事项

1. 真实 lake、NAS、provider、供应商或外部数据框架访问；以及 credential、token、secret、account 的读取。
2. 真实 ADV、liquidity、quote、order、order-book、成交、订单流、历史回填或真实数据校准。
3. 真实 capacity sizing、real market-impact / capacity calibration、真实 alpha-decay 经验估计。
4. 修改 `engine.cross_strategy_reliability_gates` 的 canonical Gate 4，或修改 `StrategyAdmissionPackage` / C1-C4 aggregate orchestration。
5. 修改 CR-168 C3-only adapter 以承载 C4 present 路径。
6. Stage 3 启动、runtime-ready / production-ready 声明、broker/QMT/simulation/paper/live/trading 操作。
7. catalog/store/registry/lake pointer 写入、publish/deploy/tag/release、Git remote write。
8. CR-155 状态提升、解除 blocked、`paper_candidate=true` 或综合 regression/promotion 决策。
9. 在 CP3 决策前实现 alpha-decay calculator，或将它作为本 CR 的完成承诺。

### Stage 2 → Stage 3 过渡控制（评审整改）

`STAGE2-EXIT-VERIFICATION.result.json` 是 CR-169 的 CP8 / 正式 Stage 2 exit 前置证据，不是对 CR-169 范围的扩张。它必须以 `7/7` 逐项核验既有 Stage 2 合同：`FactorSpec`、`FactorRunSpec`、factor panel、label window、evaluation、portfolio/risk、admission package / evidence index；C4 只补足最后一项的 fixture/static evidence-index 合同。核验失败或缺证据时不得以本 CR 的 claim ceiling 替代事实。

若历史 6 项中的任一项为 FAIL/BLOCKED，补救责任路由回 CR-157 owner 或新建治理 CR；CR-169 不得修改历史合同以“修平”结果。该缺口不改变 CR-169 本地 C4 fixture 交付是否满足自身 QAC，但会使 Stage 2 completion claim 不成立，并继续维持 `stage3_entry_ready=false`。

Stage 3 entry 继续为 `false`，并至少需要：(1) 未来经独立 CR、CP0 冲突预检和用户授权决定的 FU-007 canonical Gate 4 全局 N/A 语义硬化；(2) FU-006 或经未来人工批准的等价 independent verifier；(3) 明确的 Stage 3 data/runtime authorization。上述事项均不由 CR-169 实施。
