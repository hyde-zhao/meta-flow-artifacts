## 变更描述

实现一条仅面向 synthetic/fixture/golden-vector 的 effective-trial 方法链：从经 CP3 冻结的相关矩阵输入合同计算 sealed-trial 二阶 effective dimensionality，以独立字段、方法版本和 lineage 生成 standalone typed evidence。任何无效输入、方法不可用、版本/lineage 缺失或 evidence mismatch 都返回 typed unavailable，不得回退为 `raw_trial_count` 别名；本 CR 不把结果写入 public C1 consumer。

本 CR 是 CR-172 PATH-B 的前置，不是 activation 替代。它不需要具体策略身份、不读取真实数据、不绑定真实 producer；其 CP8 成功只表示离线方法合同可用，不能关闭 CR-172 或形成 Stage 3/admission claim。

### CP5 / CP7 / CP8 语义防误用义务

`effective_trial_count` 作为历史 envelope 字段名，不得覆盖方法语义。后续设计、实现、验证和终验必须同时证明：

1. 新 evidence 的 `estimation_method=spectral_participation_ratio`、method version/hash 与“二阶 effective dimensionality” limitation `4/4` 可读，缺一不得 present。
2. CR-173 修改 public C1 / Gate 1 / DSR / admission consumer 的生产文件数=`0`，向这些 consumer 传入新结果的调用数=`0`。
3. 把新结果解释为 Li-Ji effective independent tests、BH/FWER/Šidák/DSR/admission calibration 的正向声明数=`0`。
4. CP8 明示：`offline_method_ready` 只表示 standalone estimator ready；`public_effective_trial_count_populatable=false`、`c1_computable=false`。
5. future projection CR 应优先评估语义区分字段（例如 `effective_dimensionality`）或 versioned discriminated schema；在迁移完成前不得复用旧字段名制造双真相。

## Gotchas

- `effective_trial_count` 不是 `raw_trial_count` 的别名、重命名或缺省回退；数值偶然相等也必须有独立方法和 provenance。
- PATH-B 是 activation 前置，不是 activation；CR-173 CP8 不得把 `stage3_started`、`stage3_entry_ready` 或 admission flag 置为 true。
- “策略 X”在 CR-172 只是占位；CR-173 方法必须 strategy-agnostic，不能为了生成 golden vectors 静默固定真实策略身份。
- standalone evidence 通过不等于 public C1 可计算，也不等于方法在真实数据上有效；本 CR 只证明离线合同、确定性和失败语义。
- `effective_trial_count` 是历史兼容字段名；CR-173 v1 的严格语义是 `spectral_participation_ratio` 二阶 effective dimensionality，不得被下游解释为 Li-Ji effective independent tests 或 BH/FWER/DSR 校正数。
- 不能使用真实目录、manifest、旧 run 或字段名猜测来填补输入；缺少 CP3 冻结输入必须 typed unavailable。
