## 变更描述

将 CR-171 已确认的 `C1-C4 real-producer` 路线推进到第一段真实 evidence activation。CR-173 已完成离线 estimator，但仓库盘点证明当前没有真实 trial-return series 的生成/存储合同，现有五字段也只覆盖数据湖只读，不覆盖 multi-trial 回测 runtime。重开的 CP2 必须先决定：trial returns 从何生成、保存到何处、由谁授权；四组件部署中的数据主权和依赖方向；长期 artifact identity；以及继续走 instrumentation-first、PATH-C/A 或 typed-unavailable 降级。本 CR 当前仍只建立产品基线、决策与授权边界，不执行真实读取、运行、写入或迁移。

### PATH-B 恢复契约

1. PATH-B 是 activation 的前置，不是替代。
2. 若 CP2 选择 PATH-B，CR-172 保持 `blocked/deferred`，不得以 estimator 的 CP8 关闭 CR-172 activation。
3. CR-173 完成只证明离线 estimator 可用，不证明真实 trial-return source、multi-trial runtime、R 计算、研究机→NAS sync、执行机 materialization 或 signal transport 已存在/获授权。
4. 新发现触发当前 `requirement-clarification` 和 CP2 scope-delta 重开；本轮 CP2 推荐选择 PATH-I，先冻结上游合同和四组件部署边界，不授权真实 runtime。
5. PATH-I 完成后，只有 five fields=`5/5`、data owner identity、trial-return/storage owner、multi-trial runtime owner/授权边界、稳定 artifact URI、部署映射和 fresh conflict precheck 全部可审计，才可发起 activation-resume CP2 并选择 PATH-C 或 PATH-A。
6. activation-resume CP2/CP3 必须评估真实相关矩阵 `R` 是否属于 CR-173 v1 的 `declared_exact` 有效域。若真实 `R` 为 `empirical` 或无法证明满足该有效域，不得直接复用 v1 正向结果，并必须显式三选一：完成 `FU-CR173-001`（sampling-error/uncertainty evidence、method version 2/hash、有效域/偏差边界、独立验证）；拆分经授权的 future activation CR；或按 `DQ-CR172-003` 将 C1 binding 降级为 `effective_trial_count=typed_unavailable`、`c1_computable=false`。`FU-CR173-001` 不阻止选择降级后的 PATH-C/A 设计，但凡要输出 available effective count 或声明 `c1_computable=true`，它就是硬前置。
7. PATH-B、PATH-I 或其 CP8 均不得解释为 `stage3_started=true`、`C1 computable` 或 activation complete。

CP2 推荐冻结“逻辑 identity 与物理挂载解耦”的两层合同。lineage、manifest、evidence 和 GitHub 交付元数据只保存稳定逻辑 URI 与 content hash，不保存某台主机的绝对挂载路径作为身份。

现有单次 mature multifactor runner 不是 multi-trial family，不应为迁就新目录伪造 `family_id/trial_id`。其**新运行默认目录**推荐从：

`/home/hyde/data/quant-lab/research/runs/stage3_mature_multifactor/{run_id}/`

迁移为：

`${QUANT_LAB_RESEARCH_RUNS_ROOT}/multifactor-strategy-research/{run_id}/`

对应逻辑 URI 推荐为 `research://runs/multifactor-strategy-research/{run_id}/{artifact_name}`。`run_id` 推荐采用 `run-{UTC timestamp}-{config_hash8}`，策略、参数和准入状态写入 manifest，不继续编码进超长目录名。历史目录、历史 schema、兼容函数名和旧 artifact URI 原地保留并标记 `legacy/require-revalidation`；本轮不执行搬迁、重命名或 rewrite。实际代码默认值、CLI、文档和新运行测试只能在 CP2/CP3/CP5 通过后一起切换，避免双默认路径。

### 四组件部署与数据主权推荐

| 组件 | 主要职责 | 推荐读写边界 | 明确禁止 |

推荐数据流为：`GitHub code/config → 研究机/执行机`；`研究机本地 data-lake/research runs → hash/manifest/seal → NAS versioned replica`；`NAS 选定 release/artifact → 执行机 temporary staging → hash/manifest verify → local immutable cache`；`研究机 release packaging → NAS package-exchange + GitHub release metadata`；`NAS package-exchange → 执行机`；`执行机 local trading facts → NAS trading-archive replica`。研究 runtime 与执行 runtime 都只消费各自主机本地目录，不直接把 NAS 当工作盘。

### 研究机与执行机之间的交易信号传递

默认推荐**不传递逐笔交易信号**：研究机交付 versioned strategy package/config/model refs，执行机用自己的实时行情与本地数据副本生成信号和订单计划。这样研究机离线、NAS 同步延迟或网络抖动都不会成为 live execution 的单点故障，账户映射和下单权限也只存在执行机。

| 场景 | 推荐方案 | 传递对象 | 约束 |
|---|---|---|---|
| 日内/低延迟交易 | 执行机本地生成信号；研究机与执行机之间 signal transfer=`0` | 只传策略包、配置、模型/数据版本 refs | NAS/rsync 不满足延迟、顺序和可用性；若必须远程生成，进入 `DF-CR172-INTRADAY-REALTIME-SIGNAL`，未来独立 CR 再设计 mTLS、ordered delivery、ack/replay 与 failover |
| 日频/EOD/人工批准的低频调仓 | PATH-I 只允许冻结可选 immutable batch 的边界和最小字段 | `SignalBatch` 或 `TargetPositionBatch`，不是 broker order | 具体物理路径、七级状态机、ack、idempotency/replay、同步与消费实现转入 `DF-CR172-SIGNAL-BATCH-EXCHANGE`，不属于 PATH-I CP3/CP5 |

PATH-I 的 DQ-015 规范范围严格限制为：默认执行机本地生成；低频/EOD 只承认可选 immutable batch 类型；日内/低延迟必须独立 CR；最小字段精确为 `schema_version`、`batch_id`、`strategy_id`、`strategy_package_hash`、`content_sha256`、`signature/key_id`、`valid_from/valid_until`、`sequence_no` 共 `8/8`。禁止携带 broker credential、account secret 或可直接调用 broker 的 order command。

此前提出的多端 mailbox 物理路径、`created → ... → acked` 七级状态机、`SignalAck`、idempotency/replay、订单/成交归档回流等只保留为后续候选的输入，不是当前设计合同；CP3 不得细化，CP5 不得实现。交易订单、成交与账户事实继续由 execution/trading owner 管理，不能因 DQ-015 进入 C1 activation 的 Story、授权或 claim。

## Gotchas

- `FU-CR164-004` 才是 effective-trial；`FU-CR164-001` 是 independent Agent/model verification。
- PATH-B 是前置，不是 activation 替代；不得用 estimator CP8 关闭 CR-172。
- PATH-C 默认总计三个 activation CR；若改成 sibling slices，必须在 CP2 明示并满足六项切换条件。
- joint approval 必须是同 revision/hash 的双 ledger 记录，权限按交集解释。
- C1 binding 可在 effective count unavailable 时完成，但 `C1 computable=false`。
- producer-local failure isolation 不是 OR-pass；aggregate/admission 仍可整体 blocked。
- `output_directory` 字段不等于写授权。
- CR-172 CP8 不触发 E1，也不代表 Stage 3 entry-ready。
- `layered_returns.csv` 是因子分层 forward return，不是 trial-return series；同名“returns”不得替代对象语义验证。
- `artifact_refs` 只是指针，不能证明引用对象存在、已 seal、hash 匹配或可用于相关矩阵计算。
- NAS 是同一物理设备不等于 data lake、research archive、package exchange、trading archive 可以共用 ACL/owner/retention。
- 绝对挂载路径是部署映射，不是 lineage identity；`stage3` 是项目阶段标签，不得继续出现在新 canonical 目录命名中。
- 历史目录不因新默认路径而自动迁移；新旧默认同时可写会形成 dual truth，必须通过单一切换点和兼容只读策略避免。
