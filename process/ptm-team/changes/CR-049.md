# CR-049：用例组网约束 → 环境拓扑一致性校验与批量规划（改进计划）

## 背景

工作区实测发现关键悬空用例问题：

1. **「组网约束」frontmatter 字段不被消费**：`case_runner.py` 仅在 frontmatter 校验列表（`_OPTIONAL_FIELDS`）做存在性校验，内容从不参与执行匹配。
2. **`--env-file` 手动指定**：与用例声明无关联 → 9 个 PPPoE 用例被 node2/DUT1 拓扑执行 → `eIntfPppoeDecryptError` 等 14 个失败。
3. **`check_case_env_deps` 只做 `${ENV.*}` 字段级检查**：字段能解析即放行，无拓扑级校验 → 不报 ENV_UNSUPPORTED 而是真实执行失败。
4. **物理资源池与拓扑文件已存在，但缺「组网约束→物理」映射与调度机制**。

## 现状校准（探索核实，与调研断言的出入）

- CR-037 拓扑映射能力**已实现且有完整测试**（topo-planning 183 + topo-config 174 + test_topo_plan_cr037.py 614 行）：12 个逻辑拓扑集合（含 `node3_dut1_tg1_pppoe_link4` PPPoE 条目）、topo_id 双源提取、TopoMapper 回溯匹配、台账占用闭环、env-file 四段导出、CLI `topo-plan plan`（默认 dry-run + `--authorized`）。CR-037 process 状态仍 `active`（CP4/CP6/CP7/CP8 待执行）。
- 真实用例库（206+9 个）与 `PC-PROC-M9-03-06/07` **均在工作区**，本仓库无独立 cases 目录。
- `skills/topo-config/config/physical_pool.yaml` 是**占位模板**（7 节点全 `${PLACEHOLDER}`，SW3 含完整 pppoe-server 块）；真实数据在目标项目层 3。
- **确实缺失**：`topology_registry` 注册表、批量规划器、runner 拓扑级校验、`availability` 字段/租约语义（现有仅台账 `status: free|occupied|faulty` + 打标式 allocate/release）。
- collection 现有 `node3_dut1_tg1_pppoe_link4`（节点名 `pppoe`）；用例/模板声明的 id **`node3_dut1_tg1_sw1_pppoe_link3` 不存在**，本次新建。

## 改进目标

| 目标 | 内容 | 量化验收 |
|---|---|---|
| G1 runner 拓扑一致性校验 | case_runner 解析「组网约束」与 env 文件 `metadata.topology_id` 比对；pppoe 用例在无 PPPoE 场景 env 上标 ENV_UNSUPPORTED；`--plan-file` 批量模式 | 9 个 PPPoE 用例在 node2 env 上全部 ENV_UNSUPPORTED 而非执行失败 |
| G2 批量拓扑规划 | 按组网约束分组 → 查物理池 → 设备冲突检测（串行计划）→ 执行计划（group/cases/env_file/precheck/status）；物理不可用组整组 blocked | 全量用例一次规划产出 100% status；冲突用例 0 个并发重叠 |
| G3 物理资源可用性 | `availability: status/owner/lease_until` + 批次 acquire/release；拓扑预检清单（node3：DUT2 ping + trex-api :8001 + TE 口 is_up + SW3 PPPoE 会话） | 可用性可查询；预检失败用例被规划器标记 blocked |
| G4 悬空用例治理 | `PC-PROC-M9-03-06/07` 识别为悬空（next_hop 事实按工作区拓扑文件核实）→ 规划器报 blocked；建议改声明 node2 拓扑 | 悬空用例被显式识别并分流 |

## 工作区执行指引（层⑤⑥ 落地）

```bash
# 1. 批量规划（只读，无副作用；--pool-path/--devices-yaml/--ledger-path 用工作区层 3 真实数据）
uv run python skills/topo-planning/scripts/topo_planner.py plan \
  --cases-dir <工作区用例目录> \
  --pool-path <工作区 topology/physical_pool.yaml> \
  --devices-yaml <工作区 topology/devices.yaml> \
  --ledger-path <工作区 topology/physical_ledger.yaml> \
  --env-dir <已产出 env 文件目录> \
  --output <plan.yaml> --report-out <summary.txt>

# 2. 按规划执行（--plan-file 批量模式；pppoe 用例在 node2 env 上自动 ENV_UNSUPPORTED，
#    不再真实执行失败；blocked/no_topology 组用例同样被拦截）
uv run python skills/case-execution/scripts/case_runner.py run \
  --cases-dir <工作区用例目录> \
  --plan-file <plan.yaml> \
  --env-file <node2 env 文件> \
  --devices-yaml <工作区 devices.yaml> \
  --runs-dir <工作区 runs>

# 3. 预检清单（默认只读 list；--execute --authorized 才真机探测 ping/http）
uv run python skills/topo-planning/scripts/topo_precheck.py list \
  --topo-id node3_dut1_tg1_sw1_pppoe_link3 --env-file <node3 env 文件>
```

**node3 PPPoE 首跑前置（层⑤）**：DQ-049-02 仍 OPEN —— 需确认工作区 node3 物理拓扑
（DUT2@10.113.55.163 / trex@10.113.55.175 / SW3@10.113.55.179）就绪、SW3 PPPoE 会话可拨号、
env 文件 `metadata.topology_id=node3_dut1_tg1_sw1_pppoe_link3` 后，9 个 PPPoE 用例才可
从 ENV_UNSUPPORTED 转为真实执行。node3 env 就绪后规划器自动将 pppoe 组转 ready。
