# CR-033 ptm-te-tg-device-case-execution-and-exec-improvements

## 变更描述

统一目标包（parent CR），整合三个高耦合需求：

1. **TG 设备建模**：为 ptm-te 设备管理技能添加 TG 类型设备（type:TG，含 ip/serial_url，子类型 ixia-c/trex，硬件平台 EP/C236/J1900）。
2. **case-execution 用例执行引擎**：新建执行 skill（op_mapper 模式，SKILL.md + `scripts/case_runner.py` 兼 argparse CLI），参考 ptm-te workspace 的 exec_v4.py 执行脚本，借鉴 pytest/robot 理念但不引入框架。
3. **12 条执行改进整改**：基于单用例到 17 用例全量执行复盘的改进建议，全量分期落地。

承接 **CR-032 批次B**（exec_v4.py 代码改造，CR-032 批次A 已交付关闭，批次B 并入本 CR）。

## 背景与来源

- 来源一：ptm-te 从单用例到 17 用例全量执行复盘，沉淀 12 条改进建议（按投入产出比排序）。
- 来源二：执行工具需求参考 `/home/hyde/projects/ptm-te` 的 exec_v4.py（473 行未入库脚本，硬编码 17 用例 + DUT_URL/TG_URL）。
- 来源三：TG 设备建模诉求，为 TG 路由提供 `devices.yaml` 数据源（替代硬编码 trex-api IP）。

## 范围与目标

### 需求一 · TG 设备建模
- **做**：`devices.yaml` 新增 `tg` 块（`type:TG` + `host` + `serial_url` + `sub_type`(ixia-c|trex) + `hardware_platform`(EP|C236|J1900) + `ssh` + `api_server`）；SKILL.md 加 TG 流程 + `TG_SSH_PASSWORD`；device-reference.md 补全 6 组合；example/.env/README/执行指导 同步。
- **不做**：`collect_sysinfo` 不采 TG 快照（声明边界）；不引入 pydantic；TG 接口留 traffic-skill 拓扑。

### 需求二 · case-execution 执行引擎
- **做**：`skills/case-execution/SKILL.md` + `scripts/case_runner.py`（argparse：run/validate/dry-run；目录 glob/文件列表/单用例三入口）；复用 op_mapper execute；DUT/TG 地址从 `devices.yaml` + 拓扑 yml 读取；保留容错/重试/逆序清理/runtime_authorization；解析 `warming_up`/`post_op`/`retry`/`known_issue`；内置 dry-run 门 + `--execute` 授权门。
- **不做**：不引入 pytest/robot；不重写 op_mapper 映射层；exec_v4.py/subset 迁移后废弃。

### 需求三 · 12 条改进（P0→P3）
- **P0**：#1 #2 #3 #4 规则固化（install.py ptm-te-workflow 规则块）+ 需求一 TG 建模；**#4 补** op_mapper 新增 `fw_logout` op + case_runner cleanup 登出。
- **P1**：#5 用例文件驱动 + #10 devices.yaml 取址 + #6 envelope 统一解析（`extract_payload`）。
- **P2**：#7 失败自动诊断 + #11 结构化报告 + #12 known_issue 四态；**新增** 24 用例 md ARP 预热批量校验/补充（#3 落地，ptm-te workspace）。
- **P3**：#8 TG dry-run 真实路由 + #9 verify_loss 消费侧提取 tx/rx。
- **#1 落点**：`op_mapper._build_exec_env` 对 `tg_*` op 注入 `TREX_API_URL`（不改 ptm-atomic 本体）。

### 需求四 · 环境文件驱动（CP3 评审范围扩展，2026-07-28）
- **做**：op_mapper 新增 `resolve_env_refs(args, env_topology)` 环境解析层，与 `resolve_step_refs` 并列，在 `execute_op` 的 `build_command` 前执行（顺序：`resolve_env_refs` -> `resolve_step_refs` -> `validate_args` -> `build_command`）；用例用 `${ENV.*}` 占位符引用环境相关参数（端口/IP/next_hop/URL）；case_runner 加载 `--env-file` 环境文件（`port_mapping`/`nodes`/`links`），解析为 `env_topology` 传入 op_mapper；DUT 接口自动预配置（`fw_update_interface`）+ 用例后清理；`TREX_API_URL` 从环境文件 `${ENV.tg.url}` 解析注入。
- **不做**：框架不直接调 TG REST API（TG 操作仍经 ptm-atomic `run tg trex <action>` 原子操作）；不改变 dry-run/`--execute` 门控；不改变 session 顺序（login 仍第一步）；未含 `${ENV.*}` 的字面值 args 原样透传（向后兼容）。

## 量化成功标准

- TG 设备：**6 组合**（2 子类型 × 3 硬件平台）型号对照，**1 个** `tg` 块定义。
- case-execution：**3 种**入口零代码新增用例，消除 **3 处**硬编码 IP（DUT_URL/TG_URL/DEFAULT_API_URL），**1 个** `extract_payload(op_id, envelope)` 统一解析函数。
- 规则块：install.py 生成 **≥4 条**新规则（TG 路由 / max_loss / ARP 预热 / session 生命周期）。
- 改进覆盖：**12/12** 条落地；**1 个**新 `fw_logout` op；**24/24** 用例 md ARP 预热校验/补充。
- 结果分级：PASS / FAIL / KNOWN_FAIL / ERROR **四态**。
- 重装一致性：install.py 安装后规则与 skill 不丢失。

## 非目标（Out of Scope）

- 不引入 pytest / robot / 外部 eval 框架。

- 不做 HTML 报告（result.json + report.md 足够，HTML 进 BACKLOG）。
- 不改 traffic-skill / ngfw-install skill。

## 范围扩展记录（CP3 评审 · 环境文件驱动，2026-07-28）

### 扩展背景
CP3 评审中识别：ptm-te 编排流程的环境文件（拓扑文件）根本未被消费--设备准备 [2] 只加载 `devices.yaml`（IP/凭据），用例参数（端口/IP/next_hop）全部由 ptm-tde PC 写死后透传 op_mapper，无环境适配层。换环境（如 link3->link4）需手工逐参数适配，违背"用例一次编写、多环境执行"目标。现有 `${STEP-N.<field>}` 占位符机制（`resolve_step_refs`）是现成扩展点。

### 扩展目标
用例只描述测试意图与逻辑拓扑角色（`port1`/`port2`），环境文件描述物理映射，执行框架在执行时自动桥接。换环境只需换 `--env-file`，不改用例、不改执行脚本。
