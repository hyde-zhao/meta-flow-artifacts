# CR-038：ptm-te 集成 PPPoE 链路规划能力（SW 节点映射 + PPPoE Server/Client 配置 + 环回拓扑）

## 背景

CR-037 交付了「逻辑 topo → 物理 topo 映射 + env-file 生成」能力，但其 MVP 边界显式限定为**单 TG + 单 DUT 直连**（`node2_dut1_tg1_linkN` 系列），含 SW / 多节点拓扑在 exporter 报 `TOPO_NODE_COUNT_UNSUPPORTED`（HLD §1.3，明确「后续 CR 扩展」）。

用户现提出扩展需求：ptm-team 需实现 **PPPoE 链路规划能力**。参考场景为已人工调通的 PPPoE 环回链路（TG1 TE 实例 → SW2 → DUT2 TE0_8 →(PPPoE 拨号)→ SW3 GE0/1 → SW3 GE0/9 → SW1 → TG1 TE2_1，双向发流 0 丢包）。

**两个已确认边界（用户拍板）**：
1. **交付形态 = 扩展 topo 引擎（通用能力）**，非固化单条链路。
2. **SW 节点纳入自动拓扑映射**（突破 CR-037 MVP 单 TG+单 DUT 直连边界）。

## 影响面

见 frontmatter `impact_*_refs`。核心：
- **capability**：ptm-te 测试执行全链路，新增 PPPoE 链路规划能力（SW 节点映射 + PPPoE Server/Client 配置 + 环回拓扑）。
- **module**：physical_pool（多实例 TRex 消费）、topo_mapper（SW 显式节点 + 显式优先）、exporter（突破 MVP + 多实例导出 + interface_kind 透传）、switch_configurator + commands（PPPoE 命令）、pool_merge（SW 归并 + 多实例归并 + 占位符解析）、devices.yaml + device-reference（SW 设备）、case_runner（env-file SW 契约）、topology-collection（PPPoE 建模）、ptm-te.md（编排）。
- **policy**：ADR-09 env-file 契约需扩展 sw 类占位符；CR-037 MVP 边界显式突破。
- **data**：physical_pool SW 节点已预留；devices.yaml 需扩展 switch 块。
- **runtime**：H3C SW（telnet）、NGFW（PPPoE Client）、trex-api（验证）。

## 与 CR-037 的关系

本 CR 是 CR-037 的**自然延续**（`parent_cr: CR-037`），兑现其 HLD §1.3「后续 CR 扩展」的承诺：
- CR-037 的 topo-config / topo-planning 引擎、三层文件结构、ledger 占用闭环、ADR-09 产物契约、install 安装链路**全部复用**。
- 本 CR 增量：SW 显式节点映射、PPPoE Server/Client 配置生成、环回拓扑 env-file、MVP 边界放宽、SW 设备 schema/别名。

## 需求理解框架（待 meta-pm 阶段零调研 + 场景发现细化）

1. **SW 节点映射**：topo_mapper 支持 `node_type=SW` 作为显式逻辑节点匹配（当前仅 L2 透传），SW 节点进入映射结果与 env-file。
2. **PPPoE Server 配置**：switch_configurator 新增 PPPoE 命令族（`pppoe-server bind virtual-template`、`Virtual-Template` 的 `ppp authentication-mode` / `remote address pool`、`ip pool`、`local-user` ppp service-type、`ip binding vpn-instance` 复用现有 VRF），三厂商命令模板（H3C 为参考实现）。
3. **PPPoE Client 配置**：NGFW 侧 PPPoE 拨号（DUT2 TE0_8 拨号获 163.0.0.x），需 ptm-atomic 原子操作 / factor-library 扩展。
4. **环回拓扑 env-file**：exporter 突破 `_validate_mvp_topology`，支持 TG+DUT+SW 多节点 + 环回链路；env-file 契约扩展 SW 节点占位符（如 `${ENV.sw.*}`）。
5. **SW 设备 schema**：devices.yaml 新增 switch 设备块（host/role/device_type/hardware_platform）；device-reference 新增 SW 平台别名（H3C 等）。
6. **验证**：TG 双向发流（trex-traffic）验证 PPPoE 链路 0 丢包。
7. **多实例 TRex**：TG 主机并跑 GE（:8000）/TE（:8001）双实例，topo-config/topo-planning 消费 `trex_instances` 汇总块 + 接口级 `instance` 归属字段（CP2 反馈范围补充）。

## 安全与授权约束（沿用 CR-037 / ADR）

- 凭据一律 `${ENV_VAR}` 占位，禁止明文（ADR-02）；local-user 密码保持设备 cipher 密文。
- 默认 `--dry-run`；真机下发（H3C telnet / NGFW web / trex）为独立 `runtime_authorization` 决策项。
- 现有 GE 实例（GE1_1~4）正在测试，禁止改动其进程/cfg/wrapper。
