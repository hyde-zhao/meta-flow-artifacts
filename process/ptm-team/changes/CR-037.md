# CR-037：ptm-te 集成 topo 管理功能（逻辑 topo -> 物理 topo 映射 + 产物 env-file 生成 + 可选真机部署）

## 背景

ptm-te（测试执行工程师）当前执行用例前需要人工维护 `topology/topology.yaml`（port_mapping/nodes/links）。需求：集成 topo 管理能力，根据**用例逻辑 topo + 用户 topo-limit** 自动从物理资源池抽取空闲可用设备，完成逻辑 topo → 物理 topo 映射，产出 ptm-te 可直接消费的 env-file（`topology/topology.yaml`）。

核心场景（用户原话）："我需要在海光3250上执行这个用例，其中需要包含 TE|10GE 链路"。映射需结合 `devices.yaml`（真实设备）与 `physical_pool.yaml`（接线/端口/台账）完成。

**本 CR 基线 = 需求澄清 + 评审意见核实结论**。方案初稿经评审（4 事实错误 / 6 范围遗漏 / 3 建议优化），本 CR 逐项核实修正，见 §事实核对结论。

## 影响面

见 frontmatter `impact_*_refs`。核心：
- **capability**：ptm-te 测试执行全链路，新增拓扑映射前置能力
- **module**：topo-config（mapper/pool/ledger 增强）、topo-planning（新建 4 模块）、install.py、ptm-te.md、device-management（平台别名消费）
- **policy**：ADR-09 / ADR-02 / ADR-08 / device-reference.md
- **runtime**：物理资源池（海光3250 + TE）、NGFW Web API（可选下发）、trex-api（可选验证）

## 目标项目文件存放结构（三层设计）

> `physical_pool.yaml` 在 ptm-team 仓库**只存放模板/schema**；真实物理资源池放 **ptm-te 安装的目标项目**（随用户实际物理资源变化）。文件分三层：

```
┌─ 层1 模板/schema 层（ptm-team 仓库，入库）
│   skills/topo-config/config/physical_pool.yaml     # 物理池模板（示例 + 占位符 + 填写指引）
│   skills/topo-config/config/physical_ledger.yaml   # 台账模板
│   skills/device-management/templates/devices.yaml.example  # 已有
│
├─ 层2 共享资源层（~/.ptm-team/resource/，用户级，install.py resource 机制）
│   network-topology/topology-collection.md          # 逻辑 topo 描述（只读共享，12 拓扑）
│   network-topology/index.yaml
│
└─ 层3 目标项目真实数据层（ptm-te workspace，.gitignore 忽略，随实际资源变化）
    topology/
    ├── devices.yaml             # 真实设备清单（已有）
    ├── physical_pool.yaml       # 真实物理资源池/接线图（用户维护，topo 管理核心数据）
    ├── physical_ledger.yaml     # 真实设备台账（用户维护）
    ├── topology.yaml            # 默认 env-file（case-execution --env-file 默认）
    └── node2_dut1(nxp290-171_10.113.55.171)_tg1(...)_link4.yml  # 描述性命名 env-file（已有）

> 层3 真实数据（含 hg3250 设备登记）**由用户在目标项目填写维护**，ptm-team 不注入任何造数。
```

**加载优先级**：topo-planning 读目标项目 `topology/physical_pool.yaml`（真实）→ 缺省回退 skill 内模板。逻辑 topo 描述从 `~/.ptm-team/resource/network-topology/`（共享只读）。产物 env-file 写 `topology/` 下，默认 `topology.yaml` 或 `--output` 描述性命名。

**安装时首次生成（不含造数）**：`ptm-team install claude --agent ptm-te` 安装时，若目标项目 `topology/physical_pool.yaml` / `physical_ledger.yaml` 不存在，从层1模板复制生成**空白/占位模板副本**（仅 schema + 填写指引，**不含 ptm-team 测试造数**），真实数据由用户在该项目填写维护。真实数据文件沿用 `.gitignore` 的 `topology/*.yaml` 忽略规则（已有）。

### 前置数据任务（P0 · 阻断核心场景，需用户提供实际组网）

| 项 | 位置 | 说明 |
|---|---|---|
| P-1 物理池模板化 | `skills/topo-config/config/physical_pool.yaml` | ptm-team 内改为**模板**：schema + `${PLACEHOLDER}` 占位 + 填写指引。模板示例用**造数**（非真实 IP/设备）；**测试造数隔离在 ptm-team 测试目录（tests/fixtures 等），不随安装进入目标项目**。真实物理池数据由用户维护（对齐 devices.yaml.example 模式） |
| P-2 目标项目真实数据（用户维护，非 ptm-team 工作） | ptm-te `topology/physical_pool.yaml` + `physical_ledger.yaml` | **真实数据由用户在 ptm-te 目标项目填写维护**（含海光3250 设备登记，按 manaul 数据 hg3250-51/52 等）；install 首次安装仅生成模板副本供填写，**不注入任何测试造数**。**端口以真实接线为准不硬造**：GE 声明 `[copper, fiber]` 双介质；TE/XTE/QTE（仅光口）真实存在才声明；无 TE 口则 TE 约束映射失败反馈（不兜底） |
| P-3 台账映射对齐 | `physical_ledger.yaml` | 不硬加字段：归并层建立 `台账.model ↔ 池.device_type ↔ device-reference 平台` 三角映射，确保按平台筛选时台账空闲端口可用 |

## 产物契约（${ENV.*} 9 类占位符，ADR-09 硬契约）

产物 env-file 必须满足（源自 `topology.yaml.example` / `case-execution/SKILL.md:91-99`）：

| 占位符 | 解析路径 |
|---|---|
| `${ENV.tg.port1}` | port_mapping.port1.tg |
| `${ENV.tg.port1.ip}` | nodes.tg1.interfaces.port1.ip |
| `${ENV.tg.port1.gw}` | nodes.tg1.interfaces.port1.gw |
| `${ENV.dut.port1}` | port_mapping.port1.dut |
| `${ENV.dut.port1.ip}` | nodes.dut1.interfaces.port1.ip |
| `${ENV.tg.url}` | nodes.tg1.trex_api_url |
| `${ENV.dut.url}` | nodes.dut1.host |
| `${ENV.dut.next_hop}` | nodes.dut1.next_hop |
| `${ENV.tg.ports[port1,port2]}` | [port_mapping.port1.tg, port_mapping.port2.tg] |

端口名必须加引号（YAML 1.1 整数陷阱，Gotcha #11）。
