# CR-031 ptm-tse-runtime-data-governance

## 变更描述

`ptm-tse` 已安装并验证于 `/home/hyde/projects/ptm-tse/`，其运行数据已经位于该安装项目的 `data/`。用户已明确：本 CR **只**交付 `ptm-team` 中 ptm-tse Agent 与三个 Skill 的运行数据治理提示词/契约；安装后的项目在未来使用这些提示词自行完成本地数据治理。

本 CR 不读取、修改、修复或重新验证 `/home/hyde/projects/ptm-tse/data/`；不改安装器、安装 manifest、DAO、schema 或真实数据生命周期。先前对已安装文件权限和 support 位置的只读观察仅作为契约设计背景，不构成本轮待修复对象。

## 不授权范围

- credentials / secret / account read
- runtime / SaaS / production write
- trading / live / publish
- ITR GET、凭据、真实 SQLite / 快照写入、外部写入、生产操作、自动 reviewer 动作或发布

## 启动约束

- 本 CR 写入 `ptm-team/agents/ptm-tse.md` 及三个 `ptm-team/skills/*/SKILL.md` 源提示词；用户后续明确授权删除源码根的未跟踪运行/构建/迁移工件。
- `<runtime-root>` 的默认值是安装后的 ptm-tse 项目根，`<data-root>` 固定为 `<runtime-root>/data/`；不得回退到 `ptm-team` 源码根、全局用户目录或任意 CWD。
- 提示词更新本身不构成运行授权。未来只有安装项目中的 ptm-tse Agent 获得用户明确的本地运行授权后，才能修改该项目的既有权限、文件、保留状态或数据。

## 目标影响摘要

| 字段 | 内容 |
|---|---|
| 整体目标 | 在 Agent/Skill 提示词中形成一致的运行根、数据分类、权限预检、阻断与授权契约。 |
| 用户目标影响 | 已安装项目后续调用更新后的 ptm-tse 时，运行数据不会误解析到 `ptm-team`，且不合规数据会在摄取/发布前被阻断。 |
| 独立推进理由 | 这是对 CR-030 数据边界的最小契约补充，不扩大到安装或本地运行数据改造。 |
| 完成后 | 仅交付并静态验证源提示词；用户可将其安装到 ptm-tse 项目，之后由安装项目按新契约处理其 data/。 |
| 不确认影响 | 既有安装不变，但 Agent/Skill 继续缺少统一的运行根、预检和本地修复授权规则。 |
