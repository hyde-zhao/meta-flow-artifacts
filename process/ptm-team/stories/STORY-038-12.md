### 改动节点标记

- `resource/network-topology/topology-collection.md` 的 `node3_dut1_tg1_pppoe_link4` 场景，`pppoe` 节点：
  - `node_type: Mock` → `node_type: SW`
  - 删除 `sub_type: pppoe-server`（原 Mock 子类型语义，由 `role: pppoe-server` 承载）
  - `role: pppoe-server` 保持不变
  - 同步更新场景说明注释（`Mock / sub_type: pppoe-server` → `SW / role: pppoe-server`）与 Mermaid 子图样式（Mock 紫 `#f3e8ff` → SW 绿 `#e8f5e9`）

### 拓扑结构未变确认

- link1 / link2 / link3 的 `endpoints`（`node` + `interface`）与节点间连接关系（tg1↔dut1↔pppoe↔tg1）完全未改动。
- 未新增/删除任何 link，未新增/删除任何节点。
- 本场景除 pppoe（PPPoE Server）外无其它 Mock 节点，无需保持其它 Mock 节点不变。

### 与 STORY-038-01 SW 显式匹配一致性

- STORY-038-01 参照建模（`skills/topo-config/tests/test_topo_mapper_sw.py:110`）为 `dict(node_type='SW', role='pppoe-server')`，逻辑 SW/PPPoE Server 节点不携带 `sub_type`；本改动完全对齐。
- `topo_mapper._is_mock` 依据 `node_type` 判定（`'Mock' in types`），`node_type: SW` 后该节点不再作为虚拟 Mock 跳过，转为显式 SW 匹配；`_build_result` matched 分支 `role=node.role` 保留 `pppoe-server`，供 STORY-038-03/04 判定 PPPoE Server。

### 验证结果

- 改动为文档建模回填，`topology-collection.md` 非单一 YAML 文件（含多场景 Markdown 包裹），不直接走 parser 单文件加载；diff 已人工核对：仅 3 处建模标记改动，YAML 结构合法。
- 与 `topology-spec.md` §3.1 字段语义一致：`node_type` 枚举含 `SW`，`role` 为角色说明，`sub_type: pppoe-server` 属 Mock 子类型取值（SW 子类型为 `L2`），删除后语义自洽。
