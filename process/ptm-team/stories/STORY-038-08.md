### 实际字段结构（与 S02 `_merge_sw_pc` 对齐结论）

`devices.yaml.example` 新增 `switch` 块（第 4 个 device_group，`name: sw-pppoe-server`），字段为**平铺结构**：

```yaml
switch:
  host: 10.113.55.139        # 管理 IP
  role: pppoe-server         # 场景角色
  device_type: ruijie-B      # SW 型号
  hardware_platform: RG-SW   # SW 硬件平台
```

对齐结论：

- **块键名 `switch`（非 `sw`）**：`_merge_sw_pc` 的 `block_key={'SW':'switch','PC':'client'}`，按 `blk.get('host') == host` 精确匹配（`skills/topo-planning/src/pool_merge.py` L382-390）。
- **平铺 `host`（非 `management.host`）**：与现有 `firewall.host` / `tg.host` 对称；pool 侧 `physical_pool.yaml` SW 节点的 `management.host` 与 devices 侧 `switch.host` 由 `_merge_sw_pc` 关联。测试 fixture `skills/topo-planning/tests/fixtures/pool_merge/devices_sample.yaml` 已用平铺 `switch.host` 佐证。
- **回填字段**：`_merge_sw_pc` 读 `blk.get('device_type')` / `blk.get('hardware_platform')`，命中后置 `source='merged'`。示例值 `ruijie-B` / `RG-SW` 取自 `skills/topo-planning/tests/fixtures/pool_sw.sample.yaml` SW 节点（`device_type: ruijie-B` / `hardware_platform: RG-SW` / host `10.113.55.139`），`role: pppoe-server` 取自 `skills/topo-config/tests/fixtures/pool_pppoe_server.yaml`。
- **无凭据明文**：switch 块仅存元数据（host/role/device_type/hardware_platform），不引入 password；无 ssh 连接块（`_merge_sw_pc` 不消费连接字段，接口拓扑由 physical_pool.yaml 承载）。

### dry-run 对照

用真实 `pool_merge._merge_sw_pc` + 真实 `devices.yaml.example` 做 dry-run：模拟 physical_pool SW 节点（`management.host=10.113.55.139`，`device_type=None` / `hardware_platform=None`）→ 命中 `switch.host`，回填 `device_type=ruijie-B` / `hardware_platform=RG-SW`，`source='merged'`。断言通过。
