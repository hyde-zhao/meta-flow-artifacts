### 设计依据

G1 为工作区已验证回源（工作区 26/28 step PASS 实测）。canonical `skills/policy-route-execution/scripts/op_mapper.py` L705-707 仅注释声明「回滚 id 经用例 step-refs（${STEP-N.static_route_id}）或 verify 查询兜底」，**无实现**；`handle_rollback`（canonical L2339）inverse_op 分支无 `fw_config_static_route` 特殊路径，而 `fw_config_static_route` POST 不返回 id，回滚时 `fw_delete_static_route --id` 无法构造，导致静态路由跨用例残留（eRouteAlreadyExists）。本 Story 以 canonical HEAD 为基底逐块回源 G1 区，禁止整文件覆盖（dict 内容级差异逐块核对）。

### 语义变更声明（DQ-039-01=方案 A）

回源后**放弃 canonical 现有「step-refs 优先、verify 兜底」语义**：`fw_config_static_route` 回滚**无条件优先**走 verify 查询（每次回滚多一次只读 `fw_verify_static_route`，性能可忽略）；**verify 匹配失败即 EXEC_FAILED，不再降级 step-refs**。canonical L705-707 注释同步更新为「回滚 id 经无条件 verify 查询（fw_verify_static_route 按 dst_network/next_hop_addr 匹配）获取」。

### 接口设计

- 新增 `_query_static_route_id(args: dict, base_url: str, session_file: str, *, authorized: bool, timeout: int) -> Optional[Any]`。
- 匹配逻辑（与工作区一致）：
  - `dst_network` 必填，缺失返回 None。
  - `route_type` 默认 `ipv4`；经 `execute_op("fw_verify_static_route", {"route_type", "page":1, "size":100}, dry_run=False, authorized, timeout)` 查询。
  - 从 `data.response.vals`（或 `data.vals`）取列表，逐项按 `dst_network` 精确匹配。
  - `next_hop_addr` 仅当已解析为字面 IP 时参与匹配：raw args 含 `${`（占位符未解析）时置空跳过，避免回滚收到 `${ENV.*}` 时误判不匹配。
  - 多路由命中取**首个**非空 `id`；无匹配返回 None。
- `handle_rollback` 静态路由分支：`rtype=="inverse_op"` 且 `op_id=="fw_config_static_route"` 时**无条件**调用 `_query_static_route_id`；匹配则 `execute_op("fw_delete_static_route", {"id": rid}, dry_run=False, authorized, timeout, env_topology, tg_api_server)`；未匹配返回 EXEC_FAILED envelope（reason 含「静态路由回滚：verify 查询未匹配到 {dst_network} 的 id，无法清理」）。

### 数据与权限变化

无新数据模型；`fw_verify_static_route` 为既有只读 op（observation）；回滚为 --execute 路径，本 Story 用 mock/单测验证（static-only），不经真机。无外部接口新增。

### 失败路径

- `dst_network` 缺失 → `_query_static_route_id` 返回 None → EXEC_FAILED envelope。
- verify 查询返回异常 / 非 dict → 返回 None → EXEC_FAILED envelope。
- 无匹配（含 next_hop_addr 消歧后无命中）→ EXEC_FAILED envelope。
- next_hop_addr 为未解析占位符（含 `${`）→ 跳过该字段参与匹配，不报错，按 dst_network 继续匹配。

### 测试设计

`tests/test_op_mapper_rollback.py` 新增 verify 兜底四分支（mock `execute_op` / `fw_verify_static_route` 返回值）：
1. 有匹配（dst_network 命中）→ 断言调用 `fw_delete_static_route --id` 且 envelope success。
2. 多路由 + next_hop_addr 消歧 → 断言仅返回 next_hop_addr 匹配项的 id。
3. 无匹配 → 断言 EXEC_FAILED + reason 含目标 dst_network。
4. 占位符跳过（next_hop_addr=`${ENV.*}`）→ 断言仍按 dst_network 匹配，不因占位符误判。
