# STORY-038-02：SW 节点归并（pool_merge）

## 目标

- pool_merge 支持 SW 节点归并（复用 `_merge_sw_pc` 既有分支）。
- SW 节点按 `management.host` 匹配 devices.yaml `switch` 块，补齐 device_type / hardware_platform。
- `_resolve_ledger` 覆盖 SW 节点台账映射（R-F-011），归并无冲突。

## 依赖

- 无（W1 起点；pool_merge.py 后续由 STORY-038-13 合并多实例，本 Story 为首次写入方）。

## 技术说明

> 语义要点对齐（8 项）：设计依据、文件影响、接口、数据、权限、失败、测试、风险。

### 实现要点

- 复用 `_merge_sw_pc` 既有 SW 分支（node_type ∈ SW/PC/Mock），补齐：SW 节点按 `management.host` 精确匹配 devices.yaml `switch` 块，回填 `device_type` / `hardware_platform`。
- `_resolve_ledger` 覆盖 SW 节点台账映射：按 `device_id` 关联 physical_ledger，补齐 `ledger_model` / `ledger_status` 与 `port_status` 占用，与 physical_ledger 一致、无重复占用（R-F-011）。
- 不新增 `UnifiedNode` 字段（多实例字段由 STORY-038-13 新增）；不改变既有 TG/DUT 归并路径。
- 单写规则：`pool_merge.py` 与 STORY-038-13 串行，S13 为 merge_owner；本 Story 为 W1 首次写入方，只写 `_merge_sw_pc` / `_resolve_ledger` 范围内的 SW 补丁。

### 接口约定

- 输入：`UnifiedNode`（physical_pool × devices.yaml 归并后）+ devices.yaml `switch` 块。
- 输出：补齐 `device_type` / `hardware_platform` 的 `UnifiedNode`；台账 `port_status` 占用映射。
- 函数面不变（`_merge_sw_pc` / `_resolve_ledger` 既有签名），仅扩展内部分支，不新增公开接口。

### 异常处理

- `management.host` 无匹配 `switch` 块 → 不补齐 `device_type` / `hardware_platform`（字段保持 None），归并成功、不阻断（switch 块由 STORY-038-08 模板提供，缺失属数据问题非代码错误）。
- 台账 `port_status` 重复占用 → 沿用 `_resolve_ledger` 既有冲突语义，不引入新冲突规则、不重复分配同一端口。

### 测试要点

- 单测入口：`uv run --python 3.11 pytest skills/topo-planning/tests/`。
- TASK-E1-02-03：SW 归并台账映射无冲突，断言 `ledger_model` / `ledger_status` / `port_status` 与 physical_ledger 一致、无重复占用（R-F-011）。
- 回归：既有 TG/DUT 归并不破坏；dry-run 归并 diff 核对补齐字段。

### 回滚

- 纯内存归并 + 台账只读关联，无 production 写入；回滚 = 撤销 `_merge_sw_pc` / `_resolve_ledger` 新增 SW 分支，恢复既有 TG/DUT 归并行为。
- 本 Story 为首次写入方，无前置产物需回退。

### 安全约束

- 无凭据、无真机下发；台账映射只读关联 physical_ledger，不新增 production 写入。
