# ptm-tse 逆向分析能力 — 原始请求与事实摘要

## 用户请求

参考 `/home/hyde/projects/llm-wiki/llm-wiki/work/studies/ptm-team/sources/ptm-tse/` 中的文档，为 `ptm-tse` 添加逆向分析能力，并按 Meta Flow 正式流程开始设计。

## 已确认事实

- 当前 `ptm-tse` 是 planned 状态的测试架构师 / 技术 Owner；已有职责是需求分析、测试策略、用例评审、执行策略评估和工具框架评估。
- 新能力只处理**已恢复或已完成安全缓解的现网问题**；它不取代实时事件响应、事故指挥或生产修复。
- 逆向分析是完整闭环，RCA 只是子步骤。最小链路为：
  1. 问题分析：事实/证据、根因、引入点、流出原因与最近可拦截控制点；
  2. 改进分析：永久纠正措施（CA）、预防措施（PA）、横向排查；
  3. 闭环跟踪：单一 Owner、期限、短期/中期有效性验证、复发监控与关闭条件。
- 候选专属能力为 `reverse-analysis-skill` 和 `improvement-tracker-skill`；名称、边界、接口和最终文件布局尚未确认，必须经过 CP2/CP3。
- 下游改进可能指向：`ptm-tde`（用例/覆盖）、`ptm-te`（执行策略/运行反馈）、`ptm-tae`（自动化/回归）、`ptm-qa`（质量门禁/验证）与 `ptm-tm`（计划、风险、跟踪），但不得把任何建议自动执行为生产动作。

## 方法论事实（提炼，不替代原始来源）

| 方法 / 概念 | 本能力中的用途 |
|---|---|
| 8D | 区分根因、故障引入点、逃逸点、纠正与防止再发。 |
| CAPA | 将纠正行动、预防行动、有效性检查和关闭条件结构化。 |
| DMAIC | 用 Analyze → Improve → Control 支撑长期度量与复发控制。 |
| 5 Whys + 鱼骨图 | 在已锁定事实基础上枚举和验证根因假设，避免把触发器误作根因。 |
| SRE / postmortem | 无责复盘、事实时间线、缓解与永久修复分离、行动项可追踪。 |

## 当前禁止能力

- 不读取凭据、秘密、会话或账号；不直接访问设备、日志平台、抓包、工单、TAC 或知识库。
- 不执行或授权任何配置、策略、修复、缓解、发布、TAC 开单或生产写入。
- 不把未经证据验证的推测标为根因；不自动关闭 CA/PA。
- 不处理内部问题逆向分析；该范围应作为 deferred item，需后续独立 CR。
