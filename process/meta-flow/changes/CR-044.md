# CR-044 Story management consolidation

## Change Description

CR-044 implements CR-E from the streamlined roadmap. It consolidates Story management around `process/DEVELOPMENT-PLAN.yaml` as the machine truth source and adds checks for drift in legacy `STORY-BACKLOG.md`, `STORY-STATUS.md` and Feature `TASKS.md` views.

## Scope

In scope:

- Add `meta-flow story plan-check`.
- Define `process/DEVELOPMENT-PLAN.yaml` as the default Story management machine truth source.
- Validate Story IDs, duplicate entries, required status/title/wave fields and status values.
- Detect legacy `STORY-STATUS.md` status conflicts against the plan.
- Detect Story IDs in legacy `STORY-BACKLOG.md` / `STORY-STATUS.md` / Feature `TASKS.md` that do not exist in the plan.
- Update Story management guidance so `STORY-STATUS.md` and `STORY-BACKLOG.md` are generated/legacy views, not independent truth sources.

Out of scope:

- Rewriting all historical process files.
- Deleting legacy Story files.
- Migrating every Feature `TASKS.md` into the plan in this CR.
- Changing product requirements or Story boundaries.
- Repository push / remote publication execution.

## Acceptance

- `meta-flow story plan-check --project-root .` validates a consolidated plan.
- Duplicate Story IDs in `DEVELOPMENT-PLAN.yaml` fail.
- Missing required Story fields fail.
- A legacy `STORY-STATUS.md` status conflict fails.
- Legacy Story references that do not appear in the plan are reported.
- Story-manager documentation identifies `DEVELOPMENT-PLAN.yaml` as the single machine truth source and treats legacy summary files as generated compatibility views.

## Not Authorized

- Credential, secret, account, cookie, private-key or token reads.
- Runtime, SaaS, production, data publish, provider publish, lake write, live-trading or trading writes.
- Repository push / remote publication execution.
- Writes to `process/quant-lab/**`.

## Closeout

CR-044 closed as `READY_WITH_RISK` on 2026-07-04. It implements `meta-flow story plan-check`, establishes `process/DEVELOPMENT-PLAN.yaml` as the Story management machine truth source, and updates Story planning / checkpoint guidance so legacy Story backlog/status files are generated or compatibility views.

Remaining risks: legacy Story files remain readable for compatibility, and Feature `TASKS.md` dedup is drift-detected rather than fully migrated. These risks are accepted because the checker now prevents silent Story status conflicts and makes remaining drift visible.
