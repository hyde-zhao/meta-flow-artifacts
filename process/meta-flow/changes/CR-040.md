# CR-040 Governance dependency warning

## Change Description

Implement a warning-only CR lifecycle check that detects when a current CR appears to depend on an unclosed governance baseline CR touching process policy, authz, roadmap or state files.

## Scope

In scope:

- Add machine-readable governance dependency findings to CR summaries.
- Print non-blocking `WARN` entries during `meta-flow cr check` when such dependencies exist.
- Keep the finding at `NEEDS_REVIEW`; do not block CR progress.
- Add regression tests for summary and CLI warning behavior.

Out of scope:

- P2-5 checker provenance.
- P2-6 publication authz classification.
- P2-1 CP1 grading.
- P2-4 archive / backups isolation.
- P2-7 real lake validation task wrapper.
- P2-2 Story management consolidation.

## Acceptance

- If an active process/governance CR touches `process/policies`, authz, roadmap or state baseline, and another active/proposed CR references the same governance area, the target CR summary records `governance_dependency_review.decision=NEEDS_REVIEW`.
- `meta-flow cr check` prints a warning for this condition and exits 0 when there are no blockers.
- The warning includes the current CR, governance CR, overlap reason and source refs.
- Closed governance CRs do not produce warnings.
- No runtime, credential, production write or publication operations are introduced.

## Not Authorized

- Credential, secret, account, cookie, private-key or token reads.
- Runtime, SaaS, production, publish, live-trading or trading writes.
- Writes to `process/quant-lab/**`.

## Closeout

CR-040 closed as `READY_WITH_RISK` on 2026-07-04. It implements warning-only governance dependency detection in CR summaries and `meta-flow cr check`.

Remaining risk: matching policy/authz/roadmap/process-state overlap is intentionally fuzzy and may produce false positives. This is acceptable because the finding is `NEEDS_REVIEW` only and does not block CR progress.
