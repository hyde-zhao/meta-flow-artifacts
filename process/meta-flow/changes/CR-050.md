# CR-050 Governed Git branch lifecycle for CR workflows

## 变更描述

Add a deterministic, auditable CR branch lifecycle that refreshes the remote default branch, creates and publishes a CR branch, and deletes local and remote CR branches only after their tip is proven merged into the refreshed remote main branch.

## 推荐产品边界

1. 使用项目现有的原生 `git` CLI 执行边界，不安装或依赖名义不唯一的 `gb`；Git Town 仅作为未来可选 adapter 候选。
2. CR 开启时对 project 与 artifact 两仓执行：clean precheck → `fetch --prune` → 默认主分支 `pull --ff-only` → 创建同名 CR 分支 → `push -u`。
3. 发布阶段只推送已经提交的 commit；不隐式 `git add -A`、不替用户选择提交范围、不自动生成 commit 内容。
4. `merge` 是独立显式操作：所有仓先预检，按 artifact→project 把 exact published tip fast-forward 到各自 remote default；不由 publish/finish 隐式触发。
5. merge commit、squash/rebase、自动冲突解决、托管平台 API、自动审批与策略绕过不进入 MVP；非 fast-forward 或保护策略拒绝时 fail closed。
6. `finish` 必须重新 fetch 并独立证明 2/2 CR tip 已被 fresh remote default 包含，再执行精确清理；merge result 本身不是删除授权。
7. 双仓不宣称原子事务；部分成功必须输出结构化结果、保留两仓 CR branch并阻断 finish，禁止用 reset/force 回滚或补齐。

## Scenario Gray Areas 与 CP2 决策入口

| ID | 灰区 | 推荐 | 需要 CP2 确认的原因 |
|---|---|---|---|
| SGA-GB-01 | 原生 Git、`gb` 别名/工具或 Git Town | 复用原生 Git subprocess service | `gb` 没有唯一可移植契约；外部工具引入安装、配置和策略漂移。 |
| SGA-GB-02 | 只管理源码仓还是 project + artifact 成对管理 | 两仓同名分支成对管理 | process 是可恢复工作流真相的一部分，只管理源码会让跨设备证据漂移。 |
| SGA-GB-03 | 是否提供工具 merge，还是只验证外部 merge 后清理 | 独立显式 fast-forward-only merge；publish/finish不隐式触发 | 用户明确要求补齐 merge；仍需避免绕过保护/review/merge queue。 |
| SGA-GB-04 | squash/rebase 后是否按 patch 猜测已合并 | 不猜测；转 platform adapter/follow-up | Git ancestry 不成立时删除依据不足，误删风险高。 |
| SGA-GB-05 | `publish` 是否隐式 stage/commit | 只推送调用前已提交 refs | 自动选择文件或提交内容会扩大授权、混入用户未选变更并破坏可审计性。 |
| SGA-GB-06 | 两仓 merge 顺序、partial 与授权 | preflight-all；artifact→project；default-write独立授权；partial保留分支并阻断finish | 用户已批准进入产品R2，但改变CP2-DQ-03，必须重新人工冻结。 |
