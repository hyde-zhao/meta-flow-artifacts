## 当前有效基线（v2.0）

> 本节是 CR-052 当前基线。本文其余关于“CR-052 只补 migration readiness、CR-053 再真实迁移”的 v1.1 描述仅作为被重解释的历史审计材料，在 CP2 vNext 基线形成后将被正式范围和 Story 引用替代，不得继续作为实现输入。

### 用户目标

1. 每个项目有且只有一个发布库和一个过程库；发布库优先复用项目现有源码/交付仓，不新增第三个归档仓。
2. 不同项目不共享 Git working tree，任一项目切换发布分支时，其他项目看到的过程文档变化数必须为 0。
3. 过程库长期治理采用 `Project -> Roadmap -> Phase -> Work`，长期路标和阶段状态不从单次 CR/Story 反推。
4. 工作流按风险采用 G0/G1/G2；不再默认要求所有工作走固定全量 CP0-CP8 文档链。
5. 每个 Work 显式声明读集合、写集合、检查集合和 token budget；默认只读取最小充分上下文。
6. 过程库保持 main-only，但通过单写 publisher、expected-OID CAS 和可恢复重试处理并行提交；目录隔离不得被误当成 Git ref 并发已经解决。

### 推荐实施切片

| 切片 | 范围 | 首要价值 |
|---|---|---|
| A 双库隔离止痛 | 每项目独立过程库、固定项目身份、快照迁移、旧共享仓只读 | 消除跨项目分支切换文档联动 |
| B 轻量治理内核 | Project/Roadmap/Phase/Work、G0/G1/G2、Work packet | 管理长期路标并降低流程负担 |
| C 范围化执行 | scoped read/write/check、token budget、单写 publisher/CAS | 控制读取、写入、检查和 token |
| D 试点与默认切换 | meta-flow + 1 个 production 项目，各完成 2 个工作周期 | 验证恢复、兼容和治理成本 |

### 明确不做

- 不按项目重写旧共享过程仓 Git 历史；旧仓冻结为只读追溯源。
- 不把旧 CP/CR/Story 自动无损转换为新四层模型；只保留历史索引和按需查询。
- 不在首版设计分布式多写者自动 merge；过程库提交由单写 publisher 串行化。
- 不批量迁移 ptm-team、ptm-atomic、quant-lab 或其他项目；首批只做两个明确试点。
- 不因本次启动授权而执行 remote push、发布、force、reset、rebase、orphan、凭据、runtime 或 production 写入。

## 变更描述

当前共享过程归档仓和 working tree 会让一个项目的分支切换改变其他项目看到的过程文档版本；同时固定全量阶段、长上下文和全局检查使归档写入、文档读取、检查校验及 token 消耗过重。

本 CR 将 Meta Flow 重构为每项目独立发布库/过程库、`Project -> Roadmap -> Phase -> Work` 四层长期治理、G0/G1/G2 风险路由和 Work-scoped 读写检查/token 控制。首版只迁当前快照，旧共享过程仓只读保留，不拆史、不做旧对象无损转换、不批量迁移其他项目。

## 已确认事实与设计约束（v1.1 历史，已 superseded）

1. 当前 schema v1 禁止 `..`，无法表达真实 `../meta-flow-artifacts*` 拓扑；不得用放宽 traversal 修复。
2. 当前 `workspace check` 只消费 legacy STATE scalar + symlink，不能把 dual-read 兼容误报成已迁移。
3. 当前只有 `InMemoryLegResultStore`，project-local aggregate reader/store/projection 拒绝 out-of-band ref。
4. 当前 `cr branch-open` 在 CR bootstrap 使 legacy artifact process dirty 后会 fail closed；CR-052 已复现并将其作为 transitional bootstrap 输入，不提前提交半成品 CP0。
5. 删除 integration 中 inherited sibling seed 会产生 allowlisted deletion diff；验收必须区分 shared-main canonical mutation、sibling add/modify 与 seed-prune deletion。
6. 当前 steady `docs`/`process` leaf ownership 无法在含 sibling seed 的 tree 中继续“收紧”；必须先 normalize，再激活 steady route，或经 CP3 明确扩 schema。
7. 当前 artifacts exact tree 对象数是运行时事实，CR-053 必须以 fresh manifest freeze 为准，不硬编码 1592。
