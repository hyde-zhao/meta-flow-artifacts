# CR-051 Project-first artifact worktree Git lifecycle

## 变更描述

把 `meta-flow-artifacts` 的管理模型从“共享仓库整体配对”修正为“项目优先命名空间 + 每项目独立 worktree”。本 CR 先在 `meta-flow` 中开发路由、worktree 管理和 Git 生命周期能力；现有 artifact 文件迁移、目录搬迁与各源码项目软链接重挂由用户后续逐项目执行，不属于本 CR 的写入范围。

## 已确认的用户方向

1. artifact 采用项目优先的逻辑布局，目标语义为 `<project_name>/docs` 与 `<project_name>/process`。
2. 不同项目使用相互独立的 Git worktree，避免共享单一 working tree、index 和 checkout 分支。
3. 当前先完成 `meta-flow` 的 Git 周期管理与 artifact worktree 管理能力开发。
4. 现有 artifact 文件迁移和软链接挂接由用户后续逐项目实施；本 CR 只提供可验证能力、兼容读取与迁移前检查，不执行真实迁移。
5. 每个项目维护长期 `projects/<project-name>/integration` 分支；对应 artifact worktree 空闲时驻留该分支。
6. 每个正式 CR 使用 `projects/<project-name>/cr/<cr-id>-<slug>` 短期分支；CR 结束只清理短期分支，不删除项目 integration 分支。
7. 保留 `main` 作为共享 artifact 完整集成基线，但任何单个 artifact CR 均不得 refresh、merge 或直接更新 shared `main`；`main` 与项目 integration 的双向同步是 CR 外人工维护动作。
8. 一个逻辑 CR 包含 source 与 artifact 两个必需 leg：source leg 从源码仓 fresh `main/master` 创建并回到该默认分支；artifact leg 从 fresh `projects/<project>/integration` 创建并回到该 integration。两边仅共享 CR ID、关联证据和整体关闭条件。
9. 双 leg 使用单一聚合门：`BLOCKED > FAIL > IN_PROGRESS > PASS`；只有所有必需 leg 均 PASS 才能整体完成，`PARTIAL` 仅表达完成进度或部分效果，不作为成功结论；不声明跨仓原子事务，不自动回滚已成功 leg。
10. 项目 integration 首次从 fresh `origin/main` exact OID create-only 初始化；已存在时只校验/挂接，禁止 orphan、reset 或借初始化名义重新对齐。人工 main→integration 同步默认只在该项目无活跃 artifact CR 时执行。
11. 保留现有 control checkout + 可配置 sibling worktree root 拓扑，以及 project namespace/sparse/owned-path gate。

## 本轮推荐范围

### In Scope

- project-first artifact 路由模型、元数据 schema 与 legacy dual-read。
- 每项目独立 worktree 的创建、检查、列举、修复提示与安全移除能力。
- 将 CR Git 生命周期作用域从“artifact 仓库根”收紧到“当前项目对应 artifact worktree”。
- 共享仓库下 sibling project dirty 不阻断当前项目，但当前项目 worktree dirty 必须阻断危险阶段。
- 项目长期 `projects/<project-name>/integration`、项目命名空间短期 CR 分支、异构 source/artifact 双 leg、单一聚合门、integration create-only 初始化、结构化结果、dry-run 和失败恢复。
- shared `main` 与项目 integration 的人工同步计划/检查/receipt 契约；不把该同步塞入单个 CR，也不在本 CR 执行真实同步。
- 临时仓库/本地 bare remote 的自动验证、兼容文档和逐项目迁移手册。

### Out of Scope

- 搬迁 `meta-flow-artifacts` 中任何现有 `docs/**` 或 `process/**` 文件。
- 修改任何项目现有 `process`、`docs` 或 `checkpoints` 软链接。
- 在真实 `meta-flow-artifacts` 仓库创建/删除 worktree、分支、提交或远端 ref。
- 执行任何真实 `main` ↔ 项目 integration 同步或项目 integration 初始化。
- 真实远端默认分支写入、force push、历史改写、凭据读取和托管平台策略绕过。
