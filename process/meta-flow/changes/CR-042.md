# CR-042 CP1 grading and archive isolation

## Change Description

CR-042 implements CR-D from the streamlined roadmap: classify CP1 scope for existing use-case extensions and warn when archive/backups paths are mixed into non-housekeeping CR scope.

## Scope

In scope:

- Add a machine-readable `cp1_review_profile` to CR summaries.
- Classify existing use-case extension CRs as `LIGHTWEIGHT_CP1`.
- Classify product baseline refresh CRs as `FULL_CP1_REQUIRED`.
- Classify process/refactor/bugfix/docs/runtime/release CRs as `CP1_NOT_REQUIRED` unless product baseline evidence says otherwise.
- Add warning-only archive/backups isolation findings for active non-housekeeping CRs.
- Keep housekeeping process CRs allowed to touch archive/backups paths.
- Add tests for CP1 profile classification and archive/backups warning behavior.

Out of scope:

- P2-7 real lake validation task wrapper.
- P2-2 Story management consolidation.
- Changing CP1 checkpoint execution templates.
- Deleting, moving or rewriting historical archive/backups files.
- Repository push / remote publication execution.

## Acceptance

- Existing use-case extension CRs with `affected_use_cases` and no product baseline refresh receive `LIGHTWEIGHT_CP1`.
- CRs touching product baseline docs or setting `product_baseline_refresh_required=true` receive `FULL_CP1_REQUIRED`.
- Process-only CRs receive `CP1_NOT_REQUIRED` by default.
- Active feature/business CRs that list `process/archive/**` or `process/backups/**` refs receive a `NEEDS_REVIEW` archive isolation warning.
- Housekeeping process CRs that explicitly target archive/backups refs do not warn.
- `meta-flow cr check` prints archive isolation warnings without failing when no hard errors exist.

## Not Authorized

- Credential, secret, account, cookie, private-key or token reads.
- Runtime, SaaS, production, data publish, provider publish, lake write, live-trading or trading writes.
- Repository push / remote publication execution.
- Writes to `process/quant-lab/**`.

## Closeout

CR-042 closed as `READY_WITH_RISK` on 2026-07-04. It implements CP1 review-profile classification and warning-only archive/backups isolation in CR lifecycle governance.

Remaining risks: CP1 profile selection is metadata-driven, and archive/backups isolation can produce false positives for legitimate mixed-scope CRs. Both are accepted because they are review guidance / warning-only behavior, not hard gates.
