# CR-041 Checker provenance and repository publication authz

## Change Description

CR-041 implements CR-C from the streamlined roadmap: make checker/tool provenance machine-readable in CP results and split repository publication authorization from runtime/data/trading/live publish authorization.

## Scope

In scope:

- Add optional `checker_provenance` validation to CP result schema.
- Include checker provenance in rendered CP summaries and checkpoint ledger events when present.
- Add tests for valid provenance, invalid fallback records, and summary rendering.
- Add authz aliases/policy entries for repository publication:
  - `NO_REPOSITORY_PUBLICATION`
  - `REPOSITORY_PUBLICATION_ALLOWED`
- Keep repository publication separate from provider/lake/catalog publish and runtime/live publish.
- Add tests proving repository publication aliases do not grant runtime/data/trading publication.

Out of scope:

- P2-1 CP1 grading.
- P2-4 archive / backups isolation.
- P2-7 real lake validation task wrapper.
- P2-2 Story management consolidation.
- Actual `git push` execution or remote publication.

## Acceptance

- CP result may include `checker_provenance` with checker name, version/commit, invocation, generated_by and fallback fields.
- If `fallback_used=true`, `fallback_reason` and `fallback_review_ref` are required.
- CP summary and checkpoint ledger preserve provenance when present.
- Authz normalization distinguishes `repository_publication` from `provider_publish`, `catalog_publish`, `lake_write`, `runtime_connection`, `trading` and `order_write`.
- `NO_REPOSITORY_PUBLICATION` forbids repository publication without implying runtime/data/trading restrictions.
- `REPOSITORY_PUBLICATION_ALLOWED` allows repository publication without granting runtime/data/trading publish.

## Not Authorized

- Credential, secret, account, cookie, private-key or token reads.
- Runtime, SaaS, production, data publish, provider publish, lake write, live-trading or trading writes.
- Repository push / remote publication execution.
- Writes to `process/quant-lab/**`.

## Closeout

CR-041 closed as `READY_WITH_RISK` on 2026-07-04. It implements optional checker provenance in CP results and separates repository publication authorization from runtime, data, provider/lake/catalog and trading publication.

Remaining risk: historical CP results do not contain `checker_provenance`. This is accepted for backward compatibility; new CP results can carry provenance without rewriting old evidence.
