## 变更描述

用户在实际编写防火墙策略路由配置脚本时发现：仅依赖 `atomic-ops` 当前公开交付物无法生成可调用设备 API 的脚本，仍必须读取 `.input/capacity/src/api_service/policy_route.py`、`.input/capacity/data/api/default.json` 等本地输入资料，才能知道 API 路径、请求体 JSON、认证 header、三权模式和接口模式等细节。

该行为不符合当前交付边界预期：`.input/` 已被定义为本地输入 / 过程资料，不应成为用户、脚本生成器或运行时的隐式依赖。

本 CR 要求新增一个公开、非敏感、可校验的 adapter profile / spec 层，使外部配置脚本生成器可以从正式交付面读取：

- atom 操作语义：`atoms/`
- schema：`schemas/`
- package 视图：`packages/`
- adapter 映射合同：`adapters/`
- adapter profile schema 与说明文档

同时保持 `atomic-ops` CLI 的只读边界：不连接设备、不执行 atom、不下发配置、不保存凭据、不承担 runner 职责。
