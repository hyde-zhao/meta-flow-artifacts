## 背景

ptm-te 会真实执行物理用例和问题单回归，并调用 ptm-atomic 修改真实环境。失败恢复依赖每个状态变更 op 的可执行回滚策略。若 op 缺少 `side_effect` 或状态变更 op 缺少可判定的 `rollback_strategy`，ptm-te 必须默认阻断真实执行。

## 范围

### In Scope

- schema 支持 rollback 元数据字段。
- `list --format json` 暴露 rollback 摘要。
- `show <op_id> --format json` 通过完整 atom schema 暴露 rollback 字段。
- `validate --check rollback` 校验 rollback 契约。
- `rollback check --op/--plan --format json` 输出 ptm-te 可消费 readiness。
- 首批代表性 op 契约：策略路由 create/update/delete/verify、接口 update/verify、流量 start/stop/capture/verify。
- `run` 成功 envelope 尽量补 `metadata.rollback_context`。

### Out of Scope

- 不在本 CR 实现所有 79 个 atom 的完整自动回滚策略；未补齐者由 rollback validate 暴露缺口，ptm-te 默认阻断或要求人工确认。
- 不实现 ptm-te 的 rollback stack 编排。
- 不在 ptm-atomic 内自动采集设备快照；快照由 ptm-te 按 `pre_snapshot` 契约在 op 执行前调用。
- 不为不可逆 clear/reset 类操作伪造恢复能力。
