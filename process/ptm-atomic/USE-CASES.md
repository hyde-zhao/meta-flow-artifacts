## 使用场景列表（当前主基线）

### UC-05：防火墙安装

| 字段 | 内容 |
|------|------|
| **使用角色** | 防火墙交付与测试工程师 |
| **触发条件** | 需要通过串口参考流程对指定型号防火墙执行卸载安装，并把安装动作沉淀为 atomic-op 业务场景 |
| **输入** | 串口访问地址、安装包地址或引用、设备型号、管理 IP、可选完整性校验值，以及安装前识别目标设备所需的非敏感识别信息 |
| **处理逻辑** | 通过串口进入目标设备；校验当前设备身份与安装前条件；清理旧安装包、准备新安装包并校验完整性；执行卸载与安装；等待设备重启并记录安装阶段结果 |
| **输出/结果** | 安装结果记录、重启等待结果、交给后续健康检查和初始化步骤的安装完成状态 |
| **前置条件** | 能够以受控方式访问串口；安装包来源可用；目标设备已被识别为正确设备；当前场景只描述业务链路，不直接复制 `.input` 脚本实现 |
| **排除情况** | 不记录真实设备 IP、FTP 凭据或原始默认密码；不把外部脚本、日志文件命名规则或 `logs/` 目录直接带入正式交付面 |

**处理流程（文字描述）：**
1. 步骤一：通过串口识别目标设备，并核对安装前条件与安装包输入。
2. 步骤二：按参考流程执行清理、卸载、安装和重启等待，并形成安装阶段状态记录。
3. 步骤三：把安装完成状态交给健康检查与初始化场景继续处理。

### UC-06：防火墙安装后初始化

| 字段 | 内容 |
|------|------|
| **使用角色** | 防火墙交付与测试工程师 |
| **触发条件** | 防火墙完成安装并可重新通过串口登录，需要进行最小初始化以进入可管理状态 |
| **输入** | 安装完成状态、串口登录能力、管理路由参数、验证码配置目标、统一密码策略值 `Ngfw@123` |
| **处理逻辑** | 通过串口登录安装后的系统；关闭验证码；配置管理路由；将默认 Web 管理密码统一修改为 `Ngfw@123`；记录初始化成功或失败状态；仅保留用户明确指定的初始化动作 |
| **输出/结果** | 初始化结果记录、管理面可达状态、统一密码策略已应用的记录 |
| **前置条件** | 安装链路已完成；设备已重启完成并允许再次登录；初始化动作仅限用户当前确认的最小集合 |
| **排除情况** | 不把启用 SSH、恢复 license 等未被用户确认的参考动作自动纳入当前主基线；不记录旧密码明文；不写入真实管理网络地址 |

**处理流程（文字描述）：**
1. 步骤一：在安装完成后重新通过串口登录设备并确认进入可初始化状态。
2. 步骤二：执行关闭验证码、配置管理路由和统一修改默认密码三项初始化动作。
3. 步骤三：记录初始化结果，并把设备交给后续 Web 登录与状态记录场景。

| **输入** | 管理访问地址、登录用户名、目标密码策略值 `Ngfw@123`、登录接口所需的非敏感上下文 |
| **处理逻辑** | 使用配置后的密码登录防火墙；判定登录是否成功；生成登录状态记录；仅保存后续配置和验证所需的最小状态信息，不保留原始密码或完整 token 明文 |
| **输出/结果** | 登录状态记录、登录成功/失败标记、供后续配置守卫使用的会话上下文引用 |

1. 步骤一：使用初始化后统一的目标密码对防火墙执行 Web 登录。
2. 步骤二：判断登录结果并生成最小化的登录状态记录。
3. 步骤三：将登录状态输出给后续配置守卫和配置执行场景。

### UC-08：配置前检查登录状态并在失效时自动重登

| 字段 | 内容 |
|------|------|
| **使用角色** | 自动化编排开发者、防火墙交付与测试工程师 |
| **触发条件** | 需要发起配置动作，但当前登录状态未知、缺失或已失效 |
| **输入** | 目标配置任务、现有登录状态记录、登录方法引用、非敏感凭据引用 |
| **处理逻辑** | 在执行配置前先检查登录状态；若状态有效则直接进入配置；若状态缺失或失效，则调用防火墙登录方法重新登录；刷新登录状态并记录重登行为 |
| **输出/结果** | 已校验的登录上下文、重登结果记录、配置前状态守卫结果 |
| **前置条件** | 已定义登录状态的最小记录模型；配置流程能够消费登录状态检查结果 |
| **排除情况** | 不做无限重试；不把重登逻辑隐藏在配置场景内部；不要求在需求阶段决定 token 具体持久化位置 |

**处理流程（文字描述）：**
1. 步骤一：读取当前登录状态并判断其是否可用于配置动作。
2. 步骤二：若状态无效，则调用登录方法重建会话并刷新状态记录。
3. 步骤三：输出可用于配置执行的登录上下文，并保留重登审计痕迹。

### UC-10：安装/配置后的健康检查、验证与诊断收口

| 字段 | 内容 |
|------|------|
| **使用角色** | 防火墙交付与测试工程师、自动化编排开发者 |
| **触发条件** | 安装流程或配置流程执行完成，需要验证设备是否健康、配置是否生效，并在失败时收口诊断 |
| **输入** | 安装结果或配置结果、健康检查目标、验证规则、登录状态引用、诊断采样线索 |
| **处理逻辑** | 对安装链路执行 VPP、Agent、HTTPS 健康检查；对配置链路执行结果验证与必要诊断；若发现失败，则输出失败原因、诊断引用和人工介入信号；自动回滚仅作为后续评估项，不纳入当前主基线 |
| **输出/结果** | 健康检查报告、配置验证结果、失败诊断信息、人工处理提示 |
| **前置条件** | 安装或配置操作已完成；存在可验证的健康检查或配置结果；能够以非敏感方式引用诊断信息 |
| **排除情况** | 不把自动回滚作为当前主基线；不要求在本阶段定义完整日志抓取实现；不把失败时的人工处理步骤误写为已自动化能力 |

**处理流程（文字描述）：**
1. 步骤一：对安装链路执行服务健康检查，对配置链路执行生效验证。
2. 步骤二：当任一检查失败时，生成诊断引用并输出人工处理信号。
3. 步骤三：将验证结果作为场景链路闭环输出，同时保留自动回滚为后续评估项。

## 补充场景评估

| 候选补充场景 | 处理结论 | 说明 |

| 凭据 / 状态记录边界 | 纳入当前主基线（UC-07, UC-08） | 以“最小状态记录 + 不落敏感信息”方式处理 |
| 自动回滚 | 暂不纳入当前主基线 | 当前参考资料能支持诊断，但不足以形成安全的自动回滚业务基线，先作为后续评估项 |
